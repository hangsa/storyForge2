# S2 拆解 → 世界观生成 单元映射

> **文档目的**：以 S2 第一性拆解（`backend/prompts/creative/firstness_decompose.yaml`）产出的 5 维度/单元为基准，对应 WorldStep（`backend/models/world.py` + `backend/prompts/world_generation.yaml`）中可直接推演生成的世界观维度/单元。
> 若某拆解部分无对应的世界观单元，或某世界观字段无直接拆解来源，标记 **无对应单元**。

> **覆盖范围**：仅覆盖 WorldStep 的 `world.json` 写入字段（era / geography / era_social_structure / era_cultural_history / power_systems / core_rules / factions）。Stage 3 大纲、Stage 4 场景、StoryOS registries 等下游不属本表。

> **运行时说明**：S2 实际拆解的 prompt 由 `meta_decompose.yaml` 生成的 per-project 定制版本（写入 `prompt_overrides.json.firstness_decompose.system_prompt`），但产出 schema 与本表一致。

## 拆解维度一览

来自 `backend/prompts/creative/firstness_decompose.yaml`：

| # | dimension ID | 含义 | 产出单元数 | 承重题材（来自 prompt） |
|---|---|---|---|---|
| 1 | `ontology` | 系统的硬规则：世界凭何成立、违反必有代价 | 3–5（承重时 5–8） | 玄幻/仙侠、科幻、灵异/恐怖 |
| 2 | `energetics` | 核心稀缺资源：什么稀缺、如何流动 | 3–5 | 玄幻/仙侠、科幻 |
| 3 | `power_structure` | 权力结构：谁控制什么、凭什么控制 | 3–5 | 历史、都市 |
| 4 | `protagonist_engine` | 主角引擎：主角凭何驱动故事 | 3–5（承重时 5–8） | 都市、悬疑、言情 |
| 5 | `narrative_physics` | 叙事动力：冲突为何无法轻易解决 | 3–5 | 历史、灵异/恐怖、悬疑、言情 |

每个维度的"单元（unit）"是题材标签化的（仙侠:灵窍 / 都市:升迁密码 / 科幻:黑箱），同一维度在不同题材下产出的 unit_name 不同，但单元结构稳定：`{unit_name, description}`。

## 维度一：ontology（系统的硬规则）

**承重方向**：玄幻/仙侠、科幻、灵异/恐怖。

| 拆解单元特征 | 可推演生成的世界观维度/单元 | 说明 |
|---|---|---|
| 世界底层的根本算法/天道/公理类单元 | `world.core_rules[]`（世界规则） | 每条 ontology 单元直接成为一条跨体系硬规则 |
| 体系内部的运作约束/硬性条件类单元 | `power_systems[].core_rules[]`（体系规则） | 落单张体系的内部规则卡 |
| 时代级硬约束类单元（如"末法""律法严苛""灵气枯竭"） | `world.era`（时代背景） | 时代特有的不可违背景 |
| 系统边界/外部压力类单元 | `power_systems[].ceilings[]`（力量上限） 或 `world.core_rules[]` | 边界感/外部压力若落到体系层，则成 ceilings；若落到世界层，则成 core rule |

**无对应世界观单元的拆解部分**：—
（ontology 的四类特征单元都能找到归属。注：`docs/design/创意分解.md` 中的"入侵/规则覆盖"是针对特定创意的样本单元，**不是 ontology 通用 schema**。）

---

## 维度二：energetics（核心稀缺资源）

**承重方向**：玄幻/仙侠/科幻。

| 拆解单元特征 | 可推演生成的世界观维度/单元 | 说明 |
|---|---|---|
| 资源的本体定义（能兑换什么） | `power_systems[].description`（体系描述） | 体系运作原理的简要描述 |
| 资源从原始到可用的转化机制 | `power_systems[].stages[]`（阶段划分） | 等级阶梯即转化路径 |
| 获取通道与门槛 | `power_systems[].stages[]` 入口门槛 + `power_systems[].core_rules[]` | 一并落阶段与体系规则 |
| 使用代价/副作用 | `power_systems[].cost_system`（代价系统） | 直接落代价字段 |
| 不同体系间的兼容性/排斥性 | `power_systems[].core_rules[]` | 落到各体系内部规则中 |

**无对应世界观单元的拆解部分**：—
（energetics 的所有单元都直接对应到 `power_systems[]` 的某张卡的某字段）

---

## 维度三：power_structure（权力结构）

**承重方向**：历史、都市。

| 拆解单元特征 | 可推演生成的世界观维度/单元 | 说明 |
|---|---|---|
| 资源控制主体（统治集团/宗门/财阀） | `world.factions[].name` + `factions[].type`（名称/类型） | 每个权力主体直接生成一张势力卡 |
| 控制机制（资源/知识/意识形态三要素） | `world.factions[].goal`（目标） | 该势力的核心诉求（如"控制资源""垄断知识""塑造意识形态"） |
| 反抗路径主体（资源替代/知识重构/意识觉醒） | `world.factions[]`（新增势力卡，含 `.goal`） | 三个反抗路径都对应一张新势力卡，goal 字段承接路径名 |
| 普适性困境（替代方案的规模化瓶颈） | `world.core_rules[]`（世界规则） | 结构性瓶颈作为硬规则解释"为何无法突破" |
| 阶层关系/组织形态 | `world.era_social_structure`（社会结构） | 直接落社会结构 |

**无对应世界观单元的拆解部分**：—

## 维度四：protagonist_engine（主角引擎）

**承重方向**：都市、悬疑、言情。

| 拆解单元特征 | 可推演生成的世界观维度/单元 | 说明 |
|---|---|---|
| 特殊性来源（穿越/金手指/特殊血脉） | `power_systems[]`（力量体系，作为非常规体系并入） | 主角的非通用能力若构成独立规则，生成一套独立体系 |
| 能力机制：输入 | `power_systems[].description`（体系描述 — 触发条件部分） | 能力的触发/启动条件 |
| 能力机制：处理逻辑 | `power_systems[].core_rules[]`（体系规则 — 内部逻辑部分） | 能力的内在运行逻辑（区别于其他体系的核心） |
| 能力机制：输出 | `power_systems[].description` + `power_systems[].stages[]`（产出 + 阶梯） | 能力的可见效果与等级差异 |
| 所属的多重体系结构（双体系/跨界） | `power_systems[]`（多套并存） | 多张力量体系卡 |
| 主角特殊性来自时代背景（如重生、末世） | `world.era`（时代背景） | 时代级特殊性直接落时代 |
| 伪装机制（能力的表面形态 vs 真实机制） | `power_systems[].description`（描述） + 主角 character 卡 | 世界层记录能力如何呈现；"主角如何对外伪装"属 character |

**部分归属 character 步骤的拆解部分**（不在世界观范畴）：
- **每次使用都在失去什么的代价** —— 落到 `power_systems[].cost_system`（已在 energetics 覆盖，叙事必然性补充见维度五）。
- **主角本身的姓名/外貌/性格/目标/关系网** —— 整体归 character 步骤（角色卡），不在世界观 json 中存储。
- **输入/处理/输出中"输出表象"** —— 能力如何对外呈现，是 character 步骤的伪装/表达方式，不是世界观静态规则。

## 维度五：narrative_physics（叙事动力）

**承重方向**：历史、灵异/恐怖、悬疑、言情。

| 拆解单元特征 | 可推演生成的世界观维度/单元 | 说明 |
|---|---|---|
| 解决路径的封闭性（为什么无法正面解决） | `power_systems[].ceilings[]`（力量上限） | "封闭性"直接落到每套体系的天花板 |
| 核心矛盾（结构性张力源） | `world.core_rules[]`（世界规则） | "无法解决"类硬规则补到顶层规则 |
| 持久战逻辑（敌人如何变强/代价如何累积） | `world.factions[].relations`（势力关系） | 阵营间的对抗张力 |
| 持续存在的高阶压迫（天道/律法/技术奇点） | `world.era`（时代背景）或 `world.core_rules[]` | 视抽象层级选择落点 |
| 关键牺牲/代价的必然性 | `power_systems[].cost_system`（代价系统） | 使用力量的代价 |

**无对应世界观单元的拆解部分**：
- **敌人如何变强的具体路径** —— 属于故事弧（Stage 3 大纲）层面，非静态世界观。
- **每次事件触发的新矛盾类型** —— 属于场景冲突（Stage 4）层面，非静态世界观。

## 反向校验：世界观字段的拆解来源

| 世界观字段 | 直接来源维度 | 备注 |
|---|---|---|
| `world.era` 时代背景 | ontology / protagonist_engine | 时代级硬约束或主角特殊性来源 |
| `world.geography` 地理环境 | **无对应单元** | 需由 ontology（什么样的物理规则允许此地存在）+ narrative_physics（舞台规模）联合推演 |
| `world.era_social_structure` 社会结构 | power_structure | 阶层/组织直接落点 |
| `world.era_cultural_history` 历史文化 | **无对应单元** | 需由 power_structure（历史形成的格局）+ narrative_physics（持久战逻辑）联合推演 |
| `power_systems[].name` 体系名称 | energetics / protagonist_engine | 资源本体或主角非常规能力命名 |
| `power_systems[].description` 体系描述 | energetics / protagonist_engine | 资源流动 + 主角能力描述 |
| `power_systems[].stages` 阶段划分 | energetics | 资源转化阶梯 |
| `power_systems[].core_rules` 体系规则 | ontology | |
| `power_systems[].ceilings` 力量上限 | ontology / narrative_physics | 边界感 + 解决路径封闭性 |
| `power_systems[].cost_system` 代价系统 | energetics（物理代价）/ narrative_physics（叙事必然性）/ protagonist_engine（使用代价） | 三源汇入单字段；建议 prompt 引导时按"物理代价 → 叙事代价"顺序拼接 |
| `world.core_rules` 世界规则 | ontology / narrative_physics | 跨体系硬规则 |
| `world.factions[].name` 势力名称 | power_structure | |
| `world.factions[].type` 势力类型 | power_structure | |
| `world.factions[].goal` 势力目标 | power_structure | 含统治诉求与反抗路径 |
| `world.factions[].relations` 势力关系 | power_structure / narrative_physics | |

### 没有直接拆解来源的世界观字段（需多维联合推演）

| 字段 | 缺位原因 | 建议补充策略 |
|---|---|---|
| `world.geography` 地理环境 | 拆解 5 维度无对应"物理舞台"单元 | 由 ontology（规则允许的物理形态）+ narrative_physics（冲突规模）联合生成；可在 world_generation prompt 中显式追加"地理推演"环节 |
| `world.era_cultural_history` 历史文化 | 拆解 5 维度无对应"历史叙事"单元 | 由 power_structure（现格局的历史成因）+ narrative_physics（持久战的累积痕迹）联合生成；可在 world_generation prompt 中追加"历史断面"生成步骤 |

## 跨维度整体上下文

`causal_map`（5 维度因果传导链）不映射到具体的世界观字段，但应作为整体上下文喂入 `world_generation` prompt，让 LLM 在编排时代/势力/体系时保持 5 维度联动一致——目前 prompt 只接收核心矛盾（间接来源），没有显式吃 `causal_map`，是 S2 → World 链路的优化点。

---

## 实务建议

1. **WorldStep 4 个 section 重生成按钮（`era` / `power_system` / `core_rules` / `factions`）的对应**：
   - 已覆盖 5 维度中 4 个的直接映射源。
   - **缺失**：`protagonist_engine` 没有专属重生成按钮——其世界观相关产出（主角非常规力量体系）目前合入 `power_system` section 重生成，没有独立区分。建议评估是否需要在 WorldStep 增加"主角非常规体系"独立 section，或在 `power_system` 重生成中显式标注哪些卡来自 protagonist_engine。

2. **`world.geography` 与 `world.era_cultural_history` 的生成质量**：
   - 当前 prompt 把这两项作为 era 的一部分，要求 LLM 在生成时代时一并产出"地理环境"和"历史文化"。但拆解维度没有直接对应单元，LLM 容易给空话或泛泛而谈。
   - 建议在 world_generation prompt 中显式追加推演引导：
     - geography：`由 ontology 的 [列举 2-3 条单元] 决定什么样的物理舞台存在；由 narrative_physics 的 [列举 2-3 条单元] 决定冲突规模`
     - era_cultural_history：`由 power_structure 的 [列举 2-3 条单元] 反推历史成因；由 narrative_physics 的 [列举 2-3 条单元] 反推累积代价`

3. **角色卡与世界观的拆分点**：
   - protagonist_engine 的"伪装/限制机制"和"输出表象"已明确归 character 步骤。
   - 建议在 character_generation prompt 中显式引用 protagonist_engine 单元，避免与世界观重复生成"能力机制"。
