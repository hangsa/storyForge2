核心原则：**地图先服务叙事，再服务逼真**。AI 小说系统里最容易崩的不是美术，而是“角色怎么突然到了隔壁城”“东边明明有海却说一路向北到山”。所以地图系统的第一目标是：**位置一致、移动合理、地点有戏剧功能**。

建议按四层设计：

## 1. 空间模型：先做“图”，别急着做 2D/3D

最小抽象：

- **Location 地点**：场景/城镇/房间/星港/秘境。
- **Region 区域**：州、大陆层、海域、星区。
- **Route 路径**：道路、航道、传送门、密道；带方向、耗时、风险、通行条件。
- **POI 兴趣点**：祭坛、客栈、案发现场、资源点；可挂在 Location 内。
- **Event/Affiliation 事件与势力**：影响地点状态，而非一开始就画满边界。

关键属性：

```json
{
  "id": "loc_qingfeng_inn",
  "name": "青峰客栈",
  "aliases": ["山脚客栈", "悦来分号"],
  "region": "region_southern_marsh",
  "pos_hint": "青峰山南麓，距官道半里，黑水镇北门外",
  "tags": ["落脚点", "情报", "低危险"],
  "factions": ["漕帮: 友好", "盐铁司: 警戒"],
  "enter_conditions": ["夜里需暗号", "掌柜认得女主"],
  "secrets": ["地窖通 abandoned_temple"],
  "state": {"visible": true, "explored": "half", "current_name": "悦来客栈"},
  "versions": [{"chapter": 12, "state": "intact"}, {"chapter": 31, "state": "burned"}]
}
```

**坐标策略**分三档：

- 短篇/城市悬疑：相对位置 + 距离档位 `近/同街/跨区/城外` + 时间线足迹。
- 长篇玄幻/权谋：拓扑图 + 区域邻接表 + 通行耗时；坐标只用于展示，不作为真相源。
- 硬核科幻/航海：再上经纬/投影，但保留 `canon_pos` 与 `display_pos` 分离，方便改设定不炸图。

## 2. 图层设计：同一张世界，多份真相

至少六个可开关图层：

1. **地理层**：山川、海陆、季节气候。
2. **势力层**：城镇归属、关卡、控制强度、补给点。
3. **剧情层**：案发地、约会地、任务目标、禁入区。
4. **足迹层**：角色到过哪、何时到、同行者。
5. **风险层**：怪物/军警/天灾/消耗。
6. **时间层**：灾前/灾后、季节、政权更迭；章节快照必须可回滚。

重点：**把“历史状态”当一等公民**。第 12 章烧掉的客栈，第 40 章回忆杀还能用；第 31 章后的 AI 不该默认它完好。

## 3. AI 集成管线：写作前后各管一段

生成/更新流程：

1. **定尺度**：先问“这是房间级、村镇级、大陆级还是星际级？”不同尺度不混用坐标精度。
2. **先出拓扑，再出图**：生成 10–30 个关键节点与边，而不是一次性 500 个 POI。
3. **给地点配戏剧功能**：每个新地点至少回答三个问题——**谁想要这里？这里能改变什么决定？从这里离开会变难还是变贵？**
4. **写入前校验**：AI 产出移动/距离/通关条件时，运行地理断言。
5. **写入后抽取**：从正文识别地点 mention，做别名解析、归一化、状态 diff。

冲突分级很实用：

- **Blocker**：瞬移、跨不可通行区、无权限进入禁地、章节时间不够。
- **Warning**：距离导致耗时异常、气候与描述冲突、同区域密度过高。
- **Info**：新增别名、新 POI、势力态度微调。

给作者的模式开关：`严格地理` / `允许同名新增` / `禁止新增地点` / `本卷只许在 X 区域内活动`。

检索不要只靠向量。混合召回：

- 向量：找相似氛围/功能地点；
- 图遍历：附近、同区域、N 步可达、必经之路上；
- 时间过滤：按章节/闪回/预言状态取快照；
- 条件过滤：无阵营仇恨、有补给、可夜行、当前未锁。

## 4. 面向写作的输出物：地图卡，而不是一张图

每章规划/续写时，系统返回一张**地图卡**给模型：

```text
当前：黑水镇北门·亥时
可移动：
- 官道→青峰山：40 分钟，安全，会遇见盐铁司巡检
- 水路→芦苇荡：15 分钟，低-中风险，漕帮眼线
- 翻墙回城：需要女主轻功≥3；失败惊动守卫
到达钩子：青峰山地窖可通废寺；芦苇荡今晚有货船熄灯
一致性提醒：上章客栈已烧毁，不能再用“回房取剑”。
```

正文里可注入轻量标记，出版时隐藏：  
`[LOC: blackwater_gate time=亥时 weather=小雨 route_lock=water_road]`

给读者的呈现可三档：

- MVP：交互关系图 + 章节足迹时间轴。
- 进阶：Leaflet/SVG 卡通区域图，点击地点看“已知/未知/传闻”。
- 高阶： Fog of war，按主角认知逐步点亮；作者侧保留全知视图。

## 5. 存储与架构建议

小团队 MVP：Postgres 就够。

- 表：`regions / locations / routes / pois / location_states / chapters / footprints / map_assertions`
- `location_states(location_id, chapter, faction, name, accessible, destroyed, snapshot_json)` 做时间态。
- 向量列存 embedding；图关系用邻接表 `route(from,to,direction,cost,risk,conditions)`；要复杂 traversal 再迁 Neo4j。
- 事件溯源：任何地理变更都写 `map_change_log`，支持“回到第 N 章重写”。
- 编辑器多人协作：Yjs/CRDT；导出 Graphviz/Mermaid/SVG/GeoJSON。

校验器核心是一张规则表，例如：

```text
若 move(A→B) 且无 route 可达：Blocker
若 est_travel(A→B) > chapter_time_budget：Warning
若 B.accessible=false 且缺少 enter_conditions 解除：Blocker
若 POI 新增数量 > 本章地点上限：Info/Warning
若 region_density 超过阈值：Warning“可能摊大饼”
```

## 6. 最容易踩的坑

- 把地点做成“景点名录”，没有冲突和代价。
- 坐标先行：改设定成本爆炸。真相源放图与时间态，坐标只是投影。
- 忽略室内、梦境、镜中界、虚空间：它们要有自己的子图或 `space_type`。
- 新地点无限扩张：设“每章新增地点上限”和“复用率指标”。
- 势力边界画死：先用 `influence_strength` 而不是硬多边形。
- 只存当前态：必须存版本，否则倒叙和重写会污染未来章节。

## 最小可用版本，一周内可落地

1. 只支持 Location/Route/Region 三张表 + chapter snapshot。
2. 交互图谱用 Mermaid/Graphviz 渲染，点击节点显示详情。
3. 每章输出“地图卡”给 LLM；正文抽取地点回写。
4. 三条硬规则：不可瞬移、禁地需条件、耗时超章预算报警。
5. 指标：新增地点数、复用率、Blocker/Warning 数。
