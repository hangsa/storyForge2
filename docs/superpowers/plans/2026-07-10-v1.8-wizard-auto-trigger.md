# v1.8 Init Wizard: Auto-trigger + Resave Invalidation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the init wizard auto-trigger LLM generation on entering each of the 5 generative steps (no manual "开始生成" click), and have a resave of step N invalidate `completedSteps` and `data` for steps N+1..6 so downstream content re-generates on next entry.

**Architecture:** Two changes inside the existing wizard:
- A mount-time `useEffect` in each of `ConceptStep` / `WorldStep` / `CharacterStep` / `OutlineStep` / `ChapterOutlineStep` calls the step's existing `handleStart` (or `handleBatchStart` for `CharacterStep`) when data is empty and status is neither `generating` nor `error`. The 5 step components delete their `*-idle` cards (containing the "开始生成" button) and the "重试" button inside the error UI; the modal footer's "重新生成" registration widens to include `error` status so the footer is the single retry affordance.
- The `STEP_COMPLETED` reducer case in `WizardContext` detects a *resave* (`state.completedSteps.includes(action.step)`) and filters `completedSteps` to `≤ action.step` plus clears `data` keys whose owning step is `> action.step`, before applying the patch. A `STEP_DATA_KEY_TO_STEP` map records which data key belongs to which step.

**Tech Stack:** React 18 + TypeScript + Tailwind + vitest (frontend only; no backend changes). `useReducer` + `sessionStorage` already in place from the prior init-wizard plan.

// data. Used by the STEP_COMPLETED reducer to clear downstream keys on resave.
const STEP_DATA_KEY_TO_STEP: Partial<Record<keyof WizardData, number>> = {
  concept: 1,
  story_dna: 1,
  world: 2,
  characters: 3,

b) Replace the `STEP_COMPLETED` case (currently lines 93-105) with the version that handles resaves:

```ts
    case "STEP_COMPLETED": {
      const { step, patch } = action;
      const isResave = state.completedSteps.includes(step);
      let nextCompleted: number[];
      let nextData: WizardData;
      if (isResave) {
        // Resave of an already-completed step: drop everything past `step`
        // from completedSteps and clear their data keys. The current step's
        // data is replaced by the new patch.
        nextCompleted = state.completedSteps.filter((s) => s <= step);
        const cleared: Partial<WizardData> = {};
        for (const [key, value] of Object.entries(state.data)) {
          const ownerStep = STEP_DATA_KEY_TO_STEP[key as keyof WizardData];
          if (ownerStep === undefined || ownerStep <= step) {
            (cleared as Record<string, unknown>)[key] = value;
          }
        }
        nextData = { ...cleared, ...patch };
      } else {
        nextCompleted = [...state.completedSteps, step].sort((a, b) => a - b);
        nextData = { ...state.data, ...patch };
      }
      return {
        ...state,
        status: "completed",
        completedSteps: nextCompleted,
        currentStep: Math.min(step + 1, TOTAL_STEPS),
        data: nextData,
      };
    }
```
