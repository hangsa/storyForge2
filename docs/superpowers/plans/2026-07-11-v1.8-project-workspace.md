# v1.8 Project Workspace Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace `Stage4Page`'s `/stage4` route with a unified `/workspace` route offering two modes (managed dashboard / manual editor), embed Stage1–6 functionality in the manual-mode right panel, redirect legacy `/stage4|5|6` URLs, and update the sidebar to match.

**Architecture:** New `WorkspacePage` + 11 components under `components/workspace/`, plus 2 hooks (`useWorkspaceMode`, `useWorkspacePanel`) that sync URL ↔ state. `Stage4Page` content is forked into `WritingArea` (manual-mode center) and `ContextPanel` (manual-mode right) — `Stage4Page` itself is deleted after migration. App.tsx adds a `/workspace` route and 3 redirects; `MainLayout` gains a `WORKSPACE` stage alias so the sidebar still highlights on `/workspace`.

**Tech Stack:** React 18 + TypeScript + Tailwind + vitest (frontend only; no backend changes). React Router v6 (`useNavigate`, `useSearchParams`). Persisted mode via `localStorage` (`storyforge.workspace.mode`); current panel via URL `?panel=`.

**Builds on:**
- Spec: `docs/superpowers/specs/2026-07-09-v1.8-project-workspace-design.md`
- v1.8 init wizard (`InitWizardModal.finishWizard` currently navigates to `/stage1` after step 6 — see "Spec deviation" § after Tasks)

**Decomposition rationale:**
- Each `components/workspace/*` file is a focused, single-responsibility component matching the spec's component tree.
- The two hooks are pure URL↔state utilities; both are TDD-trivial (read URL → write state; write state → read URL).
- The big components (WorkspaceLayout, WritingArea, ContextPanel, ManagedDashboard) get one test file each but may contain several `<div data-testid="...">` regions.
- Stage4Page is not edited — it is migrated into WritingArea + ContextPanel and then deleted in Task 16, eliminating dead code.

**Boundary discipline:**
- WorkspacePage is the only place that knows about both modes; each mode's children know nothing about the other.
- TopBar is mode-agnostic (project meta + mode switcher); mode-specific controls live in their respective panels.
- Right panel is mode-specific (AI control center in managed; concept/world/etc. in manual). Only one mounts at a time — `WorkspaceLayout` enforces this.

## Spec deviation (resolved during planning)

**`Stage4Page` → `WorkspacePage` content size.** `Stage4Page.tsx` is 870 lines. The plan splits it into `WritingArea` (the per-scene editor) and `ContextPanel` (right-panel tabs). The chapter tree currently embedded in Stage4Page becomes `ChapterTreePanel`. The Stage5 / Stage6 inline editors are NOT migrated; they live on dedicated routes per spec § Non-Goals ("Stage5 / Stage6 inline editor polish is out of scope; existing component reused; no refactor").

**`/stage1` vs `/workspace` post-wizard.** The spec replaces `/stage4` with `/workspace` but does not mention `/stage1`. The wizard's `finishWizard` currently navigates to `/stage1` (commit `2c34018`). The post-workspace spec envisions `/workspace` as the project's hub — `/stage1` is the canvas / concept editor, a sub-page. **This plan does NOT change wizard navigation.** It is documented as a follow-up question for the user; the wizard finish should likely change to `/workspace?mode=managed` once Tasks 1–17 land. Create `frontend/src/hooks/useWorkspaceMode.ts`:

```ts
import { useCallback } from "react";
import { useSearchParams } from "react-router-dom";

export type WorkspaceMode = "managed" | "manual";
const STORAGE_KEY = "storyforge.workspace.mode";
const VALID: WorkspaceMode[] = ["managed", "manual"];

function isValid(v: string | null): v is WorkspaceMode {
  return v !== null && (VALID as string[]).includes(v);
}

export function useWorkspaceMode(): {
  mode: WorkspaceMode;
  setMode: (m: WorkspaceMode) => void;
} {
  const [params, setParams] = useSearchParams();
  const urlMode = params.get("mode");
  const stored = (() => {
    try {
      return localStorage.getItem(STORAGE_KEY);
    } catch {
      return null;
    }
  })();

  const mode: WorkspaceMode = isValid(urlMode)
    ? urlMode
    : isValid(stored)
    ? (stored as WorkspaceMode)
    : "managed";

  const setMode = useCallback(
    (m: WorkspaceMode) => {
      try {
        localStorage.setItem(STORAGE_KEY, m);
      } catch {}
      const next = new URLSearchParams(params);
      next.set("mode", m);
      setParams(next, { replace: true });
    },
    [params, setParams],
  );

  return { mode, setMode };
}
```

import { useCallback } from "react";
import { useSearchParams } from "react-router-dom";

export type WorkspacePanel =
  | "concept"
  | "world"
  | "character"
  | "outline"
  | "diagnosis"
  | "export";

const VALID: WorkspacePanel[] = [
  "concept",
  "world",
  "character",
  "outline",
  "diagnosis",
  "export",
];

function isValid(v: string | null): v is WorkspacePanel {
  return v !== null && (VALID as string[]).includes(v);
}

export function useWorkspacePanel(): {
  panel: WorkspacePanel;
  setPanel: (p: WorkspacePanel) => void;
} {
  const [params, setParams] = useSearchParams();
  const raw = params.get("panel");
  const panel: WorkspacePanel = isValid(raw) ? raw : "concept";

  const setPanel = useCallback(
    (p: WorkspacePanel) => {
      const next = new URLSearchParams(params);
      next.set("panel", p);
      setParams(next, { replace: true });
    },
    [params, setParams],
  );

  return { panel, setPanel };
}

              onFactGuard={async () => { setBusy(true); setBusy(false); }}

              onNavigateToOutline={goToOutlinePanel}
            />
          ) : null
        }

          mode === "managed" ? <ManagedAIControlPanel /> : <ContextPanel projectId={projectId} />
        }
      />

      <ModeSwitchConfirmModal
        open={confirmOpen}
        kind={confirmKind}

        currentTask={currentTask}
