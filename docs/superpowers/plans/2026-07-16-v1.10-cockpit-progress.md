# Cockpit Progress Card Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Enrich the managed-mode cockpit (`AutopilotMiddlePanel` → `CockpitView`) with four pieces of progress information that the backend SSE already pushes but the frontend silently drops at the type layer: (1) progress bar from `current_task.progress_pct`, (2) scene number parsed from `current_task.scene_id`, (3) queue position counter "队列 N/M", (4) structured queue preview "ch17·scene2 → …".

**Architecture:** Pure TypeScript + JSX change in two files. Widen the `AutopilotSession` and `CockpitViewProps` types so the structured fields the backend sends are reachable, then render the derived values inside the existing state card. No backend changes, no new components, no new tabs. Idempotent: every new render branch is gated on `undefined` / `0` checks so a backend omission degrades to the current UI rather than crashing.

**Tech Stack:** React 18 + TypeScript + Tailwind CSS · vitest

Notes:
- The progress bar is **only** rendered when `state === "running" && progress_pct > 0`. A 0% bar is hidden to avoid the misleading "empty bar = just started" implication.

- The `(60%)` suffix is appended directly to the description line so the state card stays compact.
- The `sceneNum` regex parses `scene_id` like `"17-2"` into the scene number `2`. If `scene_id` is `null`, missing, or doesn't match the pattern, the scene suffix is omitted.
