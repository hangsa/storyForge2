# v1.8 — Init Wizard: Auto-trigger & Resave Invalidation

**Date:** 2026-07-10
**Branch:** v1.8
**Status:** Draft, pending review
**Builds on:** `2026-07-09-v1.8-init-wizard-design.md`

## Context

The v1.8 init wizard modal (see prior spec) wraps the six initialization steps (concept / worldview / character / map / outline / chapter outline) as a guided, in-modal flow. Each step's UI has an "idle" card with a "开始生成" button that the user must click to trigger LLM generation, then a "重新生成" button after completion to regenerate, and a "确认修改并继续" footer button to save and advance.

This refines two pain points in that flow:

1. **Initial generation requires a manual click.** After the user enters a step, they must read the "开始生成" prompt and click the button. This is friction the user wants removed — entering a step should auto-kick generation, since "regenerate" is the only manual trigger they actually need.
2. **Resaving a step leaves stale data downstream.** If the user goes back to step N (e.g., step 5 novel outline), modifies or regenerates it, and clicks "确认修改并继续", the next step's data (e.g., step 6 chapter outline) is built on the *old* step-5 content. The user expects "修改后继续" to invalidate that stale data and force re-generation downstream.

This spec covers both changes. No backend changes are required; both are redux-style state and useEffect additions in the frontend wizard.

## Goals

1. On entering a step that has no data, auto-call the step's generation handler — no manual click required.
2. Remove the per-step "开始生成" idle card and button. Keep "重新生成" in the modal footer for manual regeneration.
3. On error, show the error message and rely on the modal footer's "重新生成" button (now visible in error state) to retry — no separate "重试" button in the error UI.
4. When a step is resaved (or regenerated then saved) and that step was already in `completedSteps`, clear `completedSteps` and `data` for all subsequent steps so they re-generate on next entry.

## Non-Goals

- Backend changes (no new endpoint, no per-step file deletion). The backend's stale data files remain on disk; they are simply overwritten when the user re-enters the step and the auto-trigger fires.
- LLM streaming / cancellation. The user has no way to abort an in-flight generation in this iteration.
- Auto-skipping the MapStep placeholder. The user keeps the explicit "跳过" click on step 4.
- Refactoring the existing handler-registration or ref-mirror patterns in each step. Changes are additive.

## Design

### 1. Auto-trigger on step entry

Each of the five auto-generatable steps (Concept / World / Character / Outline / ChapterOutline) adds a mount-time `useEffect`:

```ts
useEffect(() => {
  const noData = !wizard.data.concept;          // or .world / .characters / .novel_outline / .chapter1_outline
  if (noData && wizard.status !== "generating" && wizard.status !== "error") {
    handleStart();                                // or handleBatchStart for CharacterStep
  }
  // eslint-disable-next-line react-hooks/exhaustive-deps
}, []);
```

Because the step components are conditionally mounted via `{wizard.currentStep === N && <StepN />}`, navigating to a new step (via "确认修改并继续" → `saveStep` or via the step indicator) unmounts the previous step and mounts the new one, naturally firing the new step's mount-time effect. `CharacterStep` calls `handleBatchStart` (the default 1+2+3 batch) — the individual "仅生成X" buttons are removed since the wizard's primary path is the batch.

The condition `status !== "generating"` prevents double-firing if a previous session left the state mid-generation. The condition `status !== "error"` lets the user see the error UI and choose to retry via "重新生成" (see §2) rather than auto-firing again.

### 2. Footer "重新生成" registration widens to error state

Each step currently registers the "重新生成" and "确认修改并继续" handlers only when data exists or `status === "completed"`. With this change, the registration widens to also register "重新生成" (but not "确认修改并继续") when `status === "error"`:

```ts
// ConceptStep.tsx, WorldStep.tsx, CharacterStep.tsx, OutlineStep.tsx, ChapterOutlineStep.tsx
const canRegenerate =
  !!wizard.data.concept ||
  wizard.status === "completed" ||
  wizard.status === "error";
const canSave = !!wizard.data.concept;
wizard.setRegenerateHandler(canRegenerate ? handleStart : null, busy);
wizard.setNextHandler(canSave ? handleNext : null, busy);
```

In error state, the footer shows: `上一步` · `重新生成`. The user clicks "重新生成" to retry. There is no "重试" button inside the error UI; that affordance is now consolidated into the footer.

### 3. Remove idle UI and the "重试" button

Each of the five steps deletes:
- The `*-idle` div (e.g., `concept-idle`, `world-idle`, `character-idle`, `outline-idle`, `chapter-outline-idle`) containing the "开始生成" button.
- The "重试" button inside the `*-error` div.

Per-step UI condition collapses to:

| Condition | Renders |
|---|---|
| `wizard.data.concept` exists | Form (already shown) |
| data empty, `status === "error"` | Error banner (text only) |
| data empty, any other status | Spinner |

For `CharacterStep`, the four "仅生成X" buttons are also removed (they lived in the idle card). The "添加更多角色" buttons in the form remain.

### 4. Resave invalidates subsequent steps

`STEP_COMPLETED` in the reducer currently adds the step to `completedSteps` (idempotent), advances `currentStep`, and merges the patch into `data`. With this change, when the step is *already* in `completedSteps` (a resave), the reducer additionally:

1. Filters `completedSteps` to keep only steps `≤ action.step`.
2. Clears `data` keys for steps `> action.step` (the stale downstream content).
3. Then advances `currentStep` and applies the patch as before.

A helper maps wizard data keys to the step that owns them:

```ts
const STEP_DATA_KEY_TO_STEP: Record<keyof WizardData, number | null> = {
  concept: 1, story_dna: 1, world: 2, characters: 3,
  novel_outline: 5, chapter1_outline: 6,
};
// step 4 (Map) has no data keys
```

The reducer becomes:

```ts
case "STEP_COMPLETED": {
  const { step, patch } = action;
  const isResave = state.completedSteps.includes(step);
  let nextCompleted: number[];
  let nextData: WizardData;
  if (isResave) {
    nextCompleted = state.completedSteps.filter(s => s <= step);
    const cleared: Partial<WizardData> = {};
    for (const [key, value] of Object.entries(state.data)) {
      const ownerStep = STEP_DATA_KEY_TO_STEP[key as keyof WizardData];
      if (ownerStep === null || ownerStep === undefined || ownerStep <= step) {
        (cleared as Record<string, unknown>)[key] = value;
      }
    }
    nextData = { ...cleared, ...patch } as WizardData;
  } else {
    nextCompleted = [...state.completedSteps, step].sort((a, b) => a - b);
    nextData = { ...state.data, ...patch };
  }
  return {
    ...state,
    status: "completed",
    completedSteps: nextCompleted,
    currentStep: Math.min(step + 1, TOTAL_STEPS),
    data: nextData,
  };
}
```

`STEP_SKIPPED` (MapStep) is unchanged. The MapStep's "跳过" call still adds step 4 to `completedSteps` and advances; it is *not* a resave path because the MapStep has no `handleNext`.

`sessionStorage` persistence (`WizardProvider` `useEffect`) already serializes `completedSteps` and `data`, so the resave effect survives a reload — when the user returns, the affected downstream steps still appear "pending" in the step indicator and the auto-trigger fires when they are entered.

### 5. Backend-side stale data (known limitation)

The backend's `novel_outline.json` / `chapter1_outline.json` for invalidated steps is not deleted by this change. If the user reloads the page after a resave, the `InitWizardModal`'s hydrate logic (gated by `completedSteps.length > 0`) skips refetching — so the in-memory cleared state wins, and the auto-trigger fires correctly. If the user clears sessionStorage or opens the wizard in a fresh browser, the hydrate path rehydrates the old backend files; the user can then click "重新生成" in the footer to refresh. Addressing this requires a backend "delete downstream step files" endpoint and is out of scope.

## Behavior Reference

| Scenario | Outcome |
|---|---|
| Fresh project, open wizard → step 1 | spinner immediately; `generateConcept` called automatically |
| Step 1 complete → click "确认修改并继续" | step 2 mounts, spinner, `generateWorld` auto-called |
| Step 1 complete, click "上一步" → back on step 1 | no auto-trigger; form shown (data exists) |
| Jump from step 1 (completed) to step 5 (completed) via nav | step 5 form shown; no auto-trigger |
| Step 3 complete, click step 5 in nav, regenerate step 5, click "确认修改并继续" | step 6 data cleared, `completedSteps` = `[1,2,3,4,5]`, step 6 mounts, spinner, `generateOutline` auto-called |
| Step 3 complete, click step 5 in nav, edit step 5, click "确认修改并继续" (no regen) | same as above: step 6 invalidated and re-generated on entry |
| Auto-trigger fails (network / LLM error) | error banner shown; footer shows "上一步" + "重新生成" |
| User clicks "重新生成" in error state | retries the same `handleStart` flow |
| Close modal mid-step-3 generation, reopen | sessionStorage restores; auto-trigger condition checks `status !== "generating"` so does NOT re-fire; spinner stays. **Known pre-existing edge case** — not addressed here |
| Resave step 1 (concept) | `completedSteps` → `[1]`, data keys for steps 2–6 cleared, currentStep = 2; step 2 auto-generates |

## Testing Strategy

### WizardContext (reducer) tests

New cases:
- `STEP_COMPLETED` on a step already in `completedSteps` (resave) filters out subsequent steps and clears their data keys.
- `STEP_COMPLETED` on a step not in `completedSteps` (first save) keeps all downstream data intact.
- `STEP_COMPLETED` on step 6 (last) with resave is benign (no steps beyond 6 to clear).
- `STEP_COMPLETED` on step 1 resave clears `world`, `characters`, `novel_outline`, `chapter1_outline`.
- The cleared data round-trips through `loadPersisted` / sessionStorage correctly.

### Step component tests

- Each step's "click start" test becomes "mount calls generate X": remove the `getByTestId('x-start')` click, replace with `await waitFor(() => expect(api.generateX).toHaveBeenCalled())`.
- Each step's "shows error" test: `getByTestId('x-error')` still appears, but no "重试" button is asserted.
- `CharacterStep`: drop the four `character-type-X` button tests (those buttons are gone in the idle card). Keep the "+X" add-character tests (those buttons remain in the form).

### InitWizardModal tests

- The "完成 → 进入工作台" test: replace `getByTestId("chapter-outline-start").click()` with `await screen.findByTestId("chapter-outline-form")` (auto-trigger resolves into the form).

## Open Questions

None — user confirmed: idle UI is removed entirely, error state shows banner only (no retry button), MapStep is not auto-skipped, subsequent steps are invalidated on resave.
