# v1.9 AutopilotRunner wiring — design

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Wire the existing `AutopilotRunner` / `AutopilotSessionManager` / stage4 writing pipeline together so that `POST /api/v1/projects/{id}/autopilot/session/start` actually drives the writing of chapters — currently the session flips to `running` but the queue is empty and no loop runs, so the UI shows "running" with no progress.

**Architecture:** In-process asyncio task per project, spawned on `start`, cancelled on `stop/pause`. The runner calls an `AsyncTaskExecutor` Protocol; production wires a `AsyncStage4Executor` that invokes existing stage4 functions in-process; tests wire a `FakeStage4Executor` that monkeypatches `WriterAgent.write_scene` + `FactGuard.run` to return canned values while exercising the real `MemoryCoordinator` / `StoryOSAgent` / `CheckpointManager` / `progress.json` writes.

**Tech Stack:** Python 3.10+ · FastAPI · asyncio · existing stage4 agent layer (`WriterAgent`, `FactGuard`, `StoryOSAgent`, `SummaryArchiver`, `MemoryCoordinator`, `CheckpointManager`) · pytest-asyncio 1.2.0.

---

## 1. Context

`docs/design/storyForge-design-v1.9.md` §四 F1.9.1 (L282) commits to "AutopilotSession 驱动模式 on top of Stage 4 章节写作流水线" but explicitly defers the wiring: "v1.9 不引入新的 LLM 调用路径，只在 STAGE 4 章节写作流水线上加一个'AutopilotSession 驱动模式'". Stage 1 (session + REST + circuit breaker) and Stage 2 (SSE + frontend) shipped, but the bridge between the session state machine and the stage4 endpoints is missing.

**Bug:** `backend/api/autopilot.py:80` calls `mgr.start(cfg)` which only flips `state: stopped → running` and writes `session.json`. Nothing seeds the queue, nothing starts a loop. The UI correctly shows the session is running, but `session.queue` is `[]`, so no `task_start` / `task_complete` events ever fire, no chapter is ever written.

**Scope of this spec:** the missing wiring. The five decisions recorded during brainstorming:

| # | Decision | Choice |
|---|---|---|
| 1 | LLM dependency in CI | **B** — inject fake executor; CI uses `FakeStage4Executor` with monkeypatched `WriterAgent` |
| 2 | QueueItem granularity | **B** — one QueueItem per scene + one `archival` per chapter, so SSE events are per-scene |
| 3 | Async loop ownership | **A** — `asyncio.create_task` started from `/session/start` handler, stored in `app.state.runners[project_id]`, cancelled on `stop/pause` |
| 4 | Failure / circuit / queue-empty rules | full 6-rule set accepted (see §5) |
| 5 | Test seam | **A** — `FakeStage4Executor` monkeypatches `WriterAgent.write_scene` and `FactGuard.run`; everything else (MemoryCoordinator, StoryOSAgent, CheckpointManager, progress.json) runs for real |

## 2. Files

### Create

- `backend/conductor/autopilot_loop.py` — `AutopilotLoopService` (per-project task bookkeeping, startup recovery).
- `backend/conductor/autopilot_runner_async.py` — `AsyncTaskExecutor` Protocol, `AsyncAutopilotRunner`, `seed_queue()` pure function, `is_chapter_complete()` pure helper.
- `backend/conductor/stage4_async_executor.py` — `AsyncStage4Executor` (production) + `FakeStage4Executor` (test seam). Refactors `write_scene` / `advance_chapter` into reusable in-process functions `_write_scene_chapter()` and `_advance_chapter()` that both HTTP handlers and the executor call.
- `tests/test_autopilot_runner_async.py` — 6+ test cases for the runner + executor + seed_queue + is_chapter_complete.
- `tests/test_autopilot_loop.py` — 4+ test cases for `AutopilotLoopService` lifecycle + crash recovery.

### Modify

- `backend/api/autopilot.py` — `start_session` calls `loop_svc.ensure(...)`; `stop_session` / `pause_session` call `loop_svc.cancel(...)`; `resume_session` calls `loop_svc.ensure(...)` reusing the session's stored `config`. Add `broadcaster.publish(event)` hook so `mgr._append_event` also pushes to SSE.
- `backend/main.py` — `@app.on_event("startup")` (or lifespan context in modern FastAPI) initialises `app.state.runners = {}` + `app.state.loop_service = AutopilotLoopService()` + scans `projects/*/autopilot/session.json` for sessions in `state == running` and calls `loop_svc.ensure(...)` to resume them after a crash.
- `backend/api/stage4_writing.py` — extract `_write_scene_chapter()` and `_advance_chapter()` as public functions that both the HTTP handlers and `AsyncStage4Executor` call. The HTTP handlers become thin wrappers that JSON-encode the result. **No behavior change for HTTP callers.**
- `backend/models/autopilot_session.py` — add a write-through `mgr.fail_current_task(error: str)` helper (currently missing; the runner needs to emit `task_fail` events without losing current_task state).
- `backend/conductor/autopilot_session.py` — add `mgr.record_force_pass_internal()` (write-through wrapper around the pure `record_force_pass` helper, mirroring the existing pattern of `set_current_task` / `complete_current_task`).
- `tests/test_autopilot_api.py` — add 1-2 tests asserting `POST /start` actually spawns a runner (verified via `current_task` being set, or via SSE event being received on a follow-up `GET /events`).
- `pytest.ini` (or `pyproject.toml` — create whichever is more idiomatic) — `asyncio_mode = "auto"` so the existing `pytest-asyncio==1.2.0` install can run async test functions without per-test decorators.

### Not touched

- `backend/conductor/autopilot_runner.py` — the existing **sync** runner is kept. `tests/test_autopilot_runner.py` continues to pass. The async runner is a sibling, not a replacement.
- Frontend — zero changes. `useAutopilotSession` / `ManagedStartModal` / `AutopilotMiddlePanel` already consume the SSE events the runner will now actually emit.
- `backend/conductor/circuit_breaker.py` — kept as-is. The runner reads events from it via `get_events()` and translates to `session.circuit.force_pass_count`.

### `backend/conductor/autopilot_loop.py`

```python
class AutopilotLoopService:
    """Per-project asyncio task bookkeeping. Lives in app.state.loop_service."""

    def __init__(self) -> None:
        self._tasks: dict[str, asyncio.Task] = {}
        self._lock = asyncio.Lock()

    async def ensure(
        self,
        project_id: str,
        mgr: AutopilotSessionManager,
        executor: AsyncTaskExecutor,
        cfg: ManagedStartConfig,
    ) -> None:
        """Spawn a runner task for project_id if not already running. Idempotent."""
        async with self._lock:
            existing = self._tasks.get(project_id)
            if existing and not existing.done():
                return
            outline = read_outline(project_id)         # may raise; caller wraps in 400
            progress = read_progress(project_id)       # may be None → treat as empty
            novel_outline = read_novel_outline(project_id)  # may be None
            seeded = await seed_queue(mgr, outline, progress, novel_outline, cfg)
            if seeded == 0:
                # Nothing to do — don't spawn a loop that would immediately exit.
                # (e.g. all_planned scope but everything's already done)
                mgr.stop()
                return
            task = asyncio.create_task(
                _runner_loop_task(self, project_id, mgr, executor, cfg),
                name=f"autopilot-{project_id}",
            )
            self._tasks[project_id] = task

    async def cancel(self, project_id: str) -> None:
        """Cancel + await the task. No-op if no task exists."""
        task = self._tasks.get(project_id)
        if task is None:
            return
        task.cancel()
        try:
            await task
        except (asyncio.CancelledError, Exception):
            pass  # _runner_loop_task swallows + cleans up

    def is_running(self, project_id: str) -> bool:
        task = self._tasks.get(project_id)
        return task is not None and not task.done()

    async def recover_running_sessions(self, projects_dir: Path) -> None:
        """Called from FastAPI startup. Scans projects/*/autopilot/session.json
        and re-spawns runners for sessions in 'running' state.
        Used after backend restart to resume sessions that were running when
        the process died."""
        ...


async def _runner_loop_task(
    loop_svc: AutopilotLoopService,
    project_id: str,
    mgr: AutopilotSessionManager,
    executor: AsyncTaskExecutor,
    cfg: ManagedStartConfig,
) -> None:
    """The actual loop body. Always cleans up self._tasks[project_id] in finally."""
    runner = AsyncAutopilotRunner(mgr, executor, cadence=cfg.cadence)
    try:
        await runner.run()
    finally:
        # remove from registry even on cancel / exception
        loop_svc._tasks.pop(project_id, None)
```

### `backend/conductor/stage4_async_executor.py`

```python
class AsyncStage4Executor:
    """Production executor. Calls stage4 functions IN-PROCESS (no HTTP self-call).
    All four chatty bits of stage4 (MemoryCoordinator, StoryOSAgent,
    CheckpointManager, progress.json write) are reused unchanged.
    """

    def __init__(self, mgr: AutopilotSessionManager, projects_dir: Path) -> None:
        self._mgr = mgr
        self._projects_dir = projects_dir

    async def execute(self, item: QueueItem, project_id: str) -> dict:
        if item.kind == "write_scene":
            return await self._write_scene(item, project_id)
        if item.kind == "archival":
            return await self._archival(item, project_id)
        raise ValueError(f"AsyncStage4Executor: unsupported kind {item.kind!r}")

    async def _write_scene(self, item, project_id) -> dict:
        chapter = item.chapter_number
        scene = item.payload["scene_number"]
        result = await _write_scene_chapter(  # extracted from stage4_writing.py
            project_id=project_id,
            chapter_number=chapter,
            scene_number=scene,
        )
        # 6-rule: check if this chapter is now complete → enqueue archival
        progress = _read_progress(project_id)
        outline = _read_outline(project_id)
        ch_p = next((c for c in progress.get("chapters", []) if c["chapter_number"] == chapter), None)
        ch_o = next((c for c in outline.get("chapters", []) if c["chapter_number"] == chapter), None)
        if ch_p and ch_o and is_chapter_complete(ch_p.get("scenes", []), ch_o.get("scene_plan", [])):
            self._mgr.add_queue_item(QueueItem(
                id=f"archive-{chapter}",
                kind="archival",
                chapter_number=chapter,
                priority=10,   # ahead of any next-chapter write_scene (priority 20+)
            ))
        return {"status": "ok", "scene_status": result["scene_status"]}

    async def _archival(self, item, project_id) -> dict:
        chapter = item.chapter_number
        await _advance_chapter(project_id=project_id)   # extracted from stage4_writing.py
        # 6-rule: seed next chapter's write_scene items (if any)
        progress = _read_progress(project_id)
        outline = _read_outline(project_id)
        next_ch = progress.get("current_chapter", chapter + 1)
        next_outline_ch = next(
            (c for c in outline.get("chapters", []) if c["chapter_number"] == next_ch),
            None,
        )
        if next_outline_ch is None:
            return {"status": "ok", "advanced": True, "next": None}  # runner will auto-stop
        for s in next_outline_ch.get("scene_plan", []):
            self._mgr.add_queue_item(QueueItem(
                id=f"write-{next_ch}-{s['scene_number']}",
                kind="write_scene",
                chapter_number=next_ch,
                priority=20 + s["scene_number"],
                payload={"scene_number": s["scene_number"]},
            ))
        return {"status": "ok", "advanced": True, "next": next_ch}


class FakeStage4Executor:
    """Test seam. Same control flow as AsyncStage4Executor but uses canned
    draft text + canned breaker_result, monkeypatched via conftest fixtures.
    Real MemoryCoordinator / StoryOSAgent / CheckpointManager still run."""

    def __init__(
        self,
        mgr: AutopilotSessionManager,
        projects_dir: Path,
        *,
        draft_factory: Callable[[int, int], str] | None = None,
        breaker_result: str = "passed",       # "passed" | "force_pass"
        advance_should_raise: Exception | None = None,
    ) -> None:
        self._mgr = mgr
        self._projects_dir = projects_dir
        self._draft_factory = draft_factory or (lambda c, s: f"<draft ch={c} scene={s} />")
        self._breaker_result = breaker_result
        self._advance_should_raise = advance_should_raise
        self._calls: list[dict] = []

    async def execute(self, item, project_id) -> dict:
        # Identical control flow to AsyncStage4Executor.
        if item.kind == "write_scene":
            self._calls.append({"kind": "write_scene", "chapter": item.chapter_number, "scene": item.payload["scene_number"]})
            result = await _write_scene_chapter(
                project_id=project_id,
                chapter_number=item.chapter_number,
                scene_number=item.payload["scene_number"],
                draft_factory=self._draft_factory,
                breaker_result=self._breaker_result,
            )
            # ... same is_chapter_complete + enqueue archival logic
            return {"status": "ok", "scene_status": result["scene_status"]}
        if item.kind == "archival":
            self._calls.append({"kind": "archival", "chapter": item.chapter_number})
            if self._advance_should_raise:
                raise self._advance_should_raise
            await _advance_chapter(project_id=project_id, fake=True)
            return {"status": "ok", "advanced": True}
```

## 4. Data flow

### A. start → runner spawned

```
POST /session/start { scope, cadence, policy, notify }
  → _ensure_project_exists
  → mgr = AutopilotSessionManager(pid)
  → s = mgr.start(cfg)                       # state: stopped→running, session.json write-through
  → loop_svc.ensure(pid, mgr, executor, cfg)
      → outline    = read_outline(pid)
      → progress   = read_progress(pid)
      → novel_outline = read_novel_outline(pid)
      → seed_queue(mgr, outline, progress, novel_outline, cfg)
          → for each chapter in scope:
              → for each missing/未完成 scene:
                  → mgr.add_queue_item(write_scene)  # appends queue_add event
              → (no archival here; the executor adds it after last write_scene)
      → task = asyncio.create_task(_runner_loop_task(...))
      → self._tasks[pid] = task
  → 200 { session }
```

### B. One scene execution

```
AsyncAutopilotRunner.run loop iteration:
  s = mgr.load()                             # O(1) JSON read
  if s.state != "running": return            # stop/pause broke out
  item = pick_next(s.queue)                  # min(priority)
  if item is None: mgr.stop(); return        # queue empty → auto-stop

  await step():
    mgr.set_current_task(CurrentTask(...))    # appends task_start event
    try:
      result = await executor.execute(item, pid)
        # AsyncStage4Executor:
        #   if write_scene:
        #     _write_scene_chapter()      ← real call, writes progress.json
        #     check is_chapter_complete  ← 6-rule check
        #     if complete: mgr.add_queue_item(archival)
        #   if archival:
        #     _advance_chapter()         ← real call, bumps current_chapter
        #     seed next chapter scenes    ← if next chapter exists
    except Exception as e:
      _append_event(task_fail, item_id, error)
      mgr.drop_queue(item.id)                # fail also drops (avoid infinite retry)
      mgr.fail_current_task()                # clears current_task WITHOUT emitting task_complete
      return {picked, completed: False, error}

    # Success path:
    mgr.drop_queue(item.id)                  # appends queue_drop event
    mgr.complete_current_task()              # appends task_complete, clears current_task

    # Circuit breaker: only if scene was force_passed (not for passed/skipped/exception)
    if result.get("scene_status") == "force_passed":
      self.record_force_pass()               # increments count; auto-pauses if >= 3

  await asyncio.sleep(self._cadence_delay)   # fast=0.5s / balanced=2s / careful=5s
```

### C. stop / pause interrupts

```
POST /session/stop (or pause):
  mgr.intervene(...)     # state: running → stopped (or paused), session.json write-through
  await loop_svc.cancel(pid)
    task.cancel()        # raises CancelledError in _runner_loop_task
    _runner_loop_task.finally:
      loop_svc._tasks.pop(pid, None)
    await task
```

### D. resume from paused

```
POST /session/resume:
  s = mgr.resume()        # state: paused → running
  cfg = s.config          # config was stored on session at start; reuse it
  loop_svc.ensure(pid, mgr, executor, cfg)
    # queue still has unprocessed items from before pause
    # no need to re-seed; only re-spawn the loop
```

### E. crash recovery (FastAPI restart)

```
@app.on_event("startup")
  app.state.loop_service = AutopilotLoopService()
  app.state.runners = {}    # legacy alias
  await app.state.loop_service.recover_running_sessions(settings.projects_dir)
    for each project in projects_dir:
      session = AutopilotSessionManager(pid).load()
      if session is None: continue
      if session.state != "running": continue
      # last_heartbeat_at check happens here; if > 30s old, downgrade to paused
      # (this is the spec L287 "stale session" rule)
      loop_svc.ensure(pid, mgr, AsyncStage4Executor(mgr, projects_dir), session.config)
```

## 5. Failure rules (6-rule set)

| # | Trigger | Action | Why |
|---|---|---|---|
| 1 | `WriterAgent.write_scene` 抛异常 (LLM 5xx / network / OOM) | runner emits `task_fail`; drops item; `force_pass_count` **NOT** incremented; continue next item | Hard system failure ≠ "AI wrote badly" — circuit breaker is for output quality, not infra |
| 2 | `scene_status == "force_passed"` (FactGuard 3 retries failed) | runner emits `task_complete(scene_status=force_passed)`; `force_pass_count++`; at threshold → `circuit_open` auto-pause | Per spec L258 / L287 — force_pass is the AI-quality circuit signal |
| 3 | `scene_status == "skipped"` (user-initiated) | runner emits `task_complete(scene_status=skipped)`; `force_pass_count` unchanged | User choice, not AI fault |
| 4 | `SummaryArchiver.archive_chapter` raises (archival LLM 5xx) | executor raises → runner catches → emits `task_fail`; `mgr.pause()` instead of drop; loop exits | "next chapter writes will be wrong without summary" — fail closed |
| 5 | `progress.scenes.length < outline.scene_plan.length` (partial write) | seed_queue only enqueues the missing scene_numbers; runner continues | Outline is the source of truth for expected scene count |
| 6 | `progress.scenes.length > outline.scene_plan.length` (outline was shortened) | is_chapter_complete only checks the first `len(outline.scene_plan)` scenes; the rest are ignored | Defensive: don't crash on outline edits mid-run |
| 7 | `progress.scenes.length == outline.scene_plan.length` but status includes `in_progress` (zombie) | `_write_scene_chapter` re-runs that scene_number; the status naturally becomes `completed` or `force_passed` | Last session crashed mid-write; treat as not-yet-done |
| 8 | queue exhausted while `state == running` | runner calls `mgr.stop()` and returns | All planned chapters done; user doesn't have to click stop |
| 9 | `outline.json` missing on start | `start_session` returns 400 BEFORE spawning the runner | Pre-flight check (validation lives in API layer) |
| 10 | `state != running` observed at top of loop | runner returns; `_runner_loop_task.finally` removes from `_tasks` | Defensive — covers external state mutations (intervene, manual edits) |

## 6. SSE event sourcing

`backend/utils/sse_broadcaster.py` already exists and is used by `/session/events`. Currently `_append_event` (in `models/autopilot_session.py`) writes to `session.history` but does **not** push to the broadcaster — that's a Stage 2 gap that prevented any real-time events.

This spec fixes it: every `mgr._append_event(...)` call (and every write-through helper like `add_queue_item`, `drop_queue_item`, `set_current_task`, `complete_current_task`, `fail_current_task`) calls `broadcaster.publish(event_dict)` so SSE history and history list are **sourced from the same place**.

**Implementation:** add `_publish_event(event: SessionEvent)` to `AutopilotSessionManager` (next to `save`). It checks `broadcaster is not None` (so unit tests that don't construct a broadcaster don't break) and calls `broadcaster.publish(event_dict)`. The session manager's `__init__` accepts an optional `broadcaster` param, defaulting to the module-level `autopilot.broadcaster` instance.

## 9. Out of scope (intentionally)

- **Cross-process mutex** for multi-worker uvicorn deploys. v1.9 assumes `--workers 1`. Multi-worker support requires Redis lock or a dedicated scheduler process.
- **LLM token budget management** at the runner layer. spec L520 says "编排后端零 LLM 增量" — rate limiting lives inside the stage4 agent layer.
- **Chapter failure rollback to checkpoint.** The previous "checkpoint rollback" task (deferred) is still deferred.
- **`policy="ask"` interactive decision events.** `TASK_KINDS` includes `decision` but the executor raises if asked; this is fine — `policy=ask` is a v2.0 feature.
- **Priority queue override** (user reorders scenes mid-run). v1.9 uses natural `min(priority)` ordering.
- **Replacing the HTTP `/stage4/write-scene` endpoint.** We extract the inner functions but keep the HTTP endpoint intact for direct user-driven writes (e.g. the "✎ 撰写这一章" button that the user clicks in manual mode).
- **`run` / `pause` test cleanup of `add_queue_item` SSE patch.** Done in §6 but the unit tests for `mgr._append_event` should continue to work without a broadcaster.
