## 一、目标与非目标

### 1.1 Goal

托管模式下,中栏 `AutopilotMiddlePanel` 的 Cockpit Tab 当前不展示任何量化进度信息——`AI 正在 write_scene (chapter 17)` 这句描述是唯一的"在做什么"线索,既看不到当前场景号、也看不到完成百分比、也看不到队列位置。

补齐这三类信息,**复用后端 SSE 已经在推送但前端类型层丢掉的字段**(`current_task.progress_pct` / `scene_id`,`queue[].chapter_number` / `scene_number` / `priority`),前端只需要拓宽类型 + 渲染。

### 1.2 Non-goals

- **不**改后端(后端已经在推这些字段,SSE 协议不变)
- **不**加 ETA(已确认跳过,理由:事件流没 timestamp,加 ETA 需要后端改 Direction A 之外的"已有数据"边界)
- **不**动 ManagedDashboard(已 v1.10 清理,左侧只保留章节网格 + 刷新)
- **不**动 WorkspaceLayout / WritingArea / ContextPanel / ManagedAIControlPanel
- **不**加新 tab、不拆新组件、不引入新依赖
- **不**实现 Direction B 的实时写作流(后续 spec 单独处理)
- **不**做"DAG / 治理面板"(plotPilot 的另一个差异,本次跳过)

## 二、当前数据流(已存在,本次只是消费)

### 后端 SSE 推送的 `current_task` 实际形态(摘自 `proj_cc4ca4ae/autopilot/session.json:11-19`)

```json
{
  "kind": "write_scene",
  "chapter_number": 17,
  "scene_id": null,
  "status": "active",
  "started_at": null,
  "description": "write_scene (chapter 17)",
  "progress_pct": 0
}
```

### 后端推送的 `queue[]` 实际形态

```json
{
  "id": "write-17-2",
  "kind": "write_scene",
  "chapter_number": 17,
  "scheduled_at": null,
  "priority": 22,
  "payload": { "scene_number": 2 }
}
```

### 前端 `AutopilotSession` 类型现状(`frontend/src/api/autopilot.ts:81-88`)

```ts
export interface AutopilotSession {
  project_id: string;
  state: "stopped" | "running" | "paused";
  current_task: { description: string; chapter?: number } | null;
  queue: Array<{ id: string; description: string }>;
  history: unknown[];
  config: ManagedStartConfig | null;
}
```

**问题**: 类型只声明了 `description` 和 `chapter?`,后端发的 `progress_pct` / `scene_id` / `kind` / `started_at` / queue 的 `chapter_number` / `payload` / `priority` 全部被 TypeScript 类型层丢掉,即便到了运行时数据还在,IDE 也不认、CockpitView 也无从读取。

## 三、改动清单

### 3.1 `frontend/src/api/autopilot.ts` — 拓宽类型

修改 `AutopilotSession` 接口的 `current_task` 和 `queue` 字段(行 84-85):

**Before:**

```ts
current_task: { description: string; chapter?: number } | null;
queue: Array<{ id: string; description: string }>;
```

**After:**

```ts
current_task: {
  description: string;
  kind?: string;
  chapter?: number;
  scene_id?: string | null;
  progress_pct?: number;
  started_at?: string | null;
} | null;
queue: Array<{
  id: string;
  kind?: string;
  chapter_number?: number;
  description: string;
  priority?: number;
  payload?: { scene_number?: number };
}>;
```

设计要点:
- 所有新字段标 optional(`?:`)——后端漏发某个字段时前端 TypeScript 编译不报错、运行时 `undefined` 也安全(`progress_pct > 0` 等比较直接为 false,不会崩)
- `scene_id` 是 string|null 都可能,后端 `write_scene` 起步时是 null,中间转 string,完成时再变 null,保留 nullability
- `kind` 留 string 而不是 union,因为后端可能新增 task 类型,前端不应该 hardcode 所有可能的 kind
- `priority` 留 optional,因为已经完成的 queue items 也不一定带 priority

### 3.2 `frontend/src/components/workspace/AutopilotMiddlePanel.tsx` — CockpitView 增强

修改位置:CockpitView 函数体内部、状态卡 JSX 内(`AI 正在...` 文字 + 队列预览 那一段,行 184-198 附近)。

#### 改动 A: `currentTask` 类型同步拓宽

`CockpitViewProps.currentTask` 当前是 `{ description: string; chapter?: number } | null`,同步改成与 `AutopilotSession.current_task` 一致的扩展形态,这样内部可以读 `progress_pct` / `scene_id` / `kind`。

#### 改动 B: 在 `AI 正在...` 文字下加 进度条 + 场景号

**Before**(行 184-193):

```tsx
<div
  data-testid="autopilot-cockpit-current-task"
  className="text-base font-display text-primary"
>
  {currentTask?.description
    ? `AI 正在 ${currentTask.description}${chapter ? ` · 第 ${chapter} 章` : ""}`
    : state === "running"
      ? "AI 正在准备下一任务…"
      : "AI 尚未启动"}
</div>
```

**After**:

```tsx
<div
  data-testid="autopilot-cockpit-current-task"
  className="text-base font-display text-primary"
>
  {currentTask?.description
    ? `AI 正在 ${currentTask.description}${chapter ? ` · 第 ${chapter} 章` : ""}${
        sceneNum ? ` · 第 ${sceneNum} 场景` : ""
      }${
        progressPct !== undefined && progressPct > 0 ? ` (${progressPct}%)` : ""
      }`
    : state === "running"
      ? "AI 正在准备下一任务…"
      : "AI 尚未启动"}
</div>
{state === "running" && progressPct !== undefined && progressPct > 0 && (
  <div
    className="h-1.5 w-full rounded-full bg-outline-variant overflow-hidden"
    data-testid="autopilot-cockpit-progress-bar"
  >
    <div
      className="h-full bg-primary-container transition-[width] duration-500"
      style={{ width: `${Math.min(100, Math.max(0, progressPct))}%` }}
    />
  </div>
)}
```

派生量定义(函数体内,CockpitView 函数顶部,放在 `recentEvents` 之后):

```tsx
const chapter = currentTask?.chapter;
const sceneId = currentTask?.scene_id;
const sceneNum =
  sceneId && /^\d+-(\d+)$/.test(sceneId)
    ? Number(RegExp.$1)
    : null;
const progressPct = currentTask?.progress_pct;
```

设计要点:
- **进度条只在 `state === "running" && progress_pct > 0` 时显示** —— `progress_pct === 0` 时不渲染,避免出现一根空 bar 误导用户以为"刚刚开始但其实没在跑"
- **进度条宽度 clamp 到 [0, 100]**:防御后端误发 `progress_pct = 120` 这种异常值
- **场景号从 scene_id 解析**:`scene_id` 形如 `"17-2"`,正则取第二段;无法解析(后端漏发或格式异常)时降级到 `null`,UI 不显示 "第 X 场景"
- **`(60%)` 内联在描述里** 而非单独一行:紧凑,不会让状态卡变得很高

#### 改动 C: 队列预览改为结构化 + 显示队列位置

**Before**(行 194-198):

```tsx
{queue.length > 0 && (
  <div className="text-xs font-body-ui text-system-log truncate">
    队列预览：{queue.slice(0, 3).map((q) => q.description).join(" → ")}
  </div>
)}
```

**After**:

```tsx
{queue.length > 0 && (
  <div className="space-y-1">
    <div
      className="text-xs font-body-ui text-system-log"
      data-testid="autopilot-cockpit-queue-position"
    >
      队列 {currentTask ? currentIndexInQueue + 1 : "—"}/{queue.length}
      {nextItem && (
        <>
          {" "}· 下一个: 第 {nextItem.chapter_number} 章
          {nextItem.payload?.scene_number && ` 第 ${nextItem.payload.scene_number} 场景`}
        </>
      )}
    </div>
    <div className="text-xs font-body-ui text-system-log/70 truncate">
      {queuePreview}
    </div>
  </div>
)}
```

派生量定义(放在 `progressPct` 后面):

```tsx
const currentIndexInQueue = currentTask
  ? queue.findIndex((q) => q.id === currentTask.id)
  : -1;
const nextItem =
  currentIndexInQueue >= 0
    ? queue[currentIndexInQueue + 1]
    : queue[0];
const queuePreview = queue
  .slice(0, 3)
  .map((q) => {
    const ch = q.chapter_number;
    const sn = q.payload?.scene_number;
    if (ch !== undefined && sn !== undefined) return `ch${ch}·scene${sn}`;
    return q.description;
  })
  .join(" → ");
```

设计要点:
- **队列位置 `currentIndexInQueue + 1`**:`findIndex` 返回 -1 表示"不在队列里"(可能在跑或已完成),UI 显示 "—"
- **下一个任务**:current 在队列里时取 `currentIndexInQueue + 1`,否则取 `queue[0]`(队列头)
- **队列预览降级**:有 `chapter_number + scene_number` 时显示 `ch17·scene2`,否则降级到 `description`,与"进度条显示降级"逻辑一致
- **类型补全**:这一改动需要 `CockpitViewProps.queue` 元素也带 `id` 字段(已经带了),其他字段从 `AutopilotSession.queue` 拓宽后自动可用

## 四、错误处理

| 场景 | 行为 |
|---|---|
| `current_task` 为 null 且 `state === "stopped"` | 显示 "AI 尚未启动",无进度条、无队列位置、无场景号 |
| `current_task` 为 null 且 `state === "running"` | 显示 "AI 正在准备下一任务…",无进度条(因为没有 progress_pct),队列位置显示 "—/N",队列预览仍显示 |
| `progress_pct` 为 0 或 undefined | 不显示进度条,不显示 "(0%)" 后缀(避免误导) |
| `progress_pct` 为负数或 > 100 | clamp 到 [0, 100],进度条不溢出 |
| `scene_id` 为 null 或格式异常(如 "abc") | 不显示 "第 X 场景" 后缀,描述行只显示 chapter 信息 |
| `chapter_number` 为 undefined(罕见:后端漏发) | 队列预览降级到 description,显示 "下一个: 第 ? 章"(渲染 undefined 为空字符串) |
| `queue` 为空数组 | 队列预览整段不渲染(line 194 `{queue.length > 0 && ...}` 已守) |
| `current_task.id` 在 `queue` 里找不到(刚入队还没刷 SSE) | `currentIndexInQueue === -1`,位置显示 "—","下一个" 取 `queue[0]` |
| 后端在某个字段漏发 | 全部标 optional,TypeScript 编译通过;运行时 `undefined` 安全降级 |
| SSE 断开 → 重连期间 | `status === "reconnecting"`,已有的 SSE 状态徽标会反映;进度信息基于本地最近一次 snapshot,不会闪退 |
