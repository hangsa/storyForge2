## 一、目标与非目标

### 1.1 Goal

托管模式驾驶舱 Tab 当前只显示任务描述、事件流、队列，**不镜像正在生成的场景文本**——用户只能去手动模式 `WritingArea` 看上一次写完的 draft。要让用户在托管模式下"看着 AI 一行一行写"，需要在驾驶舱新增一个**实时写作流**区块，渲染当前 scene 的文本增量。

实现这一体验需要从三个 LLM provider 拉到**字符级流式输出**、通过异步 executor 落 chunks、新增独立 SSE 端点推送到前端，再在前端缓冲渲染。

### 1.2 Non-goals

- **不**做 plotPilot 的全功能复刻：只对齐其"中栏实时镜像章节文本流"核心体验；不做 4-tab 驾驶舱、不做 DAG、不做治理面板（Direction C/D 不在本次范围）
- **不**改 `WritingArea.tsx`（手动模式编辑器）：本次是**托管模式专属**的可视化组件
- **不**改 `useAutopilotSession` 已有 hook 或 `/session/events` SSE 端点：流是独立的、额外的 SSE 连接
- **不**改 chapters 目录的 draft.md 写穿时机：流式过程在内存 + JSONL 落盘，最终场景文本仍按现有路径写入 `chapters/ch{NN}_scene_{MM}_draft.md`
- **不**加"AI 写入速度统计 / TPS / ETA" 等性能指标：scope 限定在"看得到 AI 在写"，不评估"写得有多快"
- **不**让用户在 UI 里编辑 / 保存当前 streaming 文本：这是只读实时预览
- **不**为 archival、checkpoint、rollback 等非 write_scene 任务实现流：archival 任务无文本输出，仍走现有事件流路径
- **不**改 LLM prompt 模板或温度/最大 token 等参数：流式只是暴露 provider 的现有能力

## 三、目标数据流（新增）

### 3.1 完整链路

```
LLM Provider (流式)             Provider            Writer              Executor           ChunkStore           SSE                 Frontend
messages.stream(...)  ─────►   generate_stream()  ──► write_scene_stream()  ──► _write_scene_stream()  ──► append(seq,text)  ──► /chapter-stream  ──► useChapterStream  ──► ChapterStreamPanel
                              (async generator)     (async generator)         async for delta:                                       EventSource         buffer chunks          字符光标 ▌
                                                                                  publish(scene_chunk)                                                       累加渲染
                                                                                  append_chunk_store
```

### 3.2 Chunk 边界与速率

**触发 flush（任一条件先达即 flush）：**
1. 累积 buffer 达到 **50 字符**（≈ 50 个汉字 / 100 个英文字符）
2. **80ms** 自上次 flush 以来（即使不满 50 字符也要发，避免长 token 卡死 UI）

**为什么 50 字符 / 80ms？**
- 50 字符是中等阅读速度下一个 "word-ish" 块（中文单句平均 15-25 字，50 字 ≈ 2-3 个短句），UI 渲染节奏自然
- 80ms 上限避免 LLM 单次吐出 1000 字符后 UI 卡死——前端 max-height 340px 内滚，节奏快不会卡
- 测试覆盖：模拟长 token（512 字符）必须拆成多次 flush，模拟短间隔（10 字符 + 90ms 停顿）也必须 flush

### 3.3 ChunkStore 设计

新增文件 `backend/conductor/scene_chunk_store.py`。

```python
@dataclass
class ChunkRecord:
    seq: int              # 单调递增
    chapter_number: int
    scene_number: int
    text: str             # 本次 flush 的 50 字符片段
    created_at: float     # time.time()


class SceneChunkStore:
    """每个 (project_id, chapter, scene) 一个 jsonl 文件。

    Path: <projects_dir>/<project_id>/autopilot/chunks/ch{NN}_scene_{MM}.jsonl
    每行一条 JSON: {"seq": 42, "chapter_number": 17, "scene_number": 2,
                    "text": "...", "created_at": 1700000000.0}
    """

    def __init__(self, projects_dir: Path, project_id: str,
                 chapter_number: int, scene_number: int) -> None: ...

    def append(self, text: str) -> ChunkRecord:
        """Append a chunk; assign next seq atomically. Returns the record."""

    def read_since(self, since_seq: int) -> list[ChunkRecord]:
        """Read all chunks with seq > since_seq, in order. Used by SSE on reconnect."""

    def total_text(self) -> str:
        """Concatenate all chunks' text. Used to compute the final draft."""

    def clear(self) -> None:
        """Delete the jsonl file. Called on scene_done or scene_failed."""

    @staticmethod
    def chunk_path(projects_dir, project_id, chapter, scene) -> Path:
        ...
```

**生命周期：**
- `Executor._write_scene_stream()` 起步时构造 `SceneChunkStore`，先调 `chunk_store.clear()` 防上轮残留，每 delta flush 一次
- `scene_done` 时合并所有 chunks 为完整文本，沿用现有 `chapters/ch{NN}_scene_{MM}_draft.md` 写盘路径，**写盘成功后再调 `chunk_store.clear()`**（顺序保证：draft.md 是事实源，必须先落盘）
- `scene_failed` 时同样调 `clear()`，保留 partial_text 给 UI 提示用户

**为什么是 JSONL：**
- append 模式：每个 chunk 一行 JSON，不需要重写整个文件
- 断线重连支持：`read_since(since_seq=N)` 可补发遗漏 chunks，前端按 seq 顺序重放
- 不和 session.json 混：session.json 写穿走完整 dataclass，每次小修改都要 fsync 全文件；JSONL 增量写只动一行
- 易于调试：人眼可读，行号天然对应 seq

**原子性假设（重要）：**
POSIX 上 `O_APPEND` 模式单文件追加对小于 `PIPE_BUF`（Linux 默认 4096 字节）的写入是原子的。我们每 chunk 上限 50 字符（UTF-8 字节约 50-150 字节），远低于阈值，天然安全。Windows 不保证此语义，但 storyForge2 不支持 Windows 部署，§1 已假设 Linux/macOS。**若未来迁移到 Windows 平台，需在 ChunkStore.append 加 per-chunk `threading.Lock`。**

#### 4.1.1 `backend/llm/base_provider.py` — 抽象流式接口

```python
@dataclass
class StreamChunk:
    """A single delta from an LLM stream."""
    text: str
    finish_reason: Optional[str] = None  # 最后一个 chunk 时设 "stop" / "length" / None


class BaseLLMProvider(ABC):
    # ... 既有 generate() ...

    @abstractmethod
    async def generate_stream(
        self, system_prompt: str, user_prompt: str, **kwargs
    ) -> AsyncIterator[StreamChunk]:
        """Yield text deltas as the LLM produces them.

        Last yielded chunk should have finish_reason set.
        """
        raise NotImplementedError
```

保持 `generate()` 旧签名不变，所有现有调用方不受影响。

#### 4.1.2 三个 Provider 实现 `generate_stream()`

**`backend/llm/anthropic_provider.py`**：

```python
async def generate_stream(
    self, system_prompt: str, user_prompt: str, **kwargs
) -> AsyncIterator[StreamChunk]:
    max_tokens = kwargs.get("max_tokens", self.default_max_tokens)
    temperature = kwargs.get("temperature", self.default_temperature)
    messages = [{"role": "user", "content": user_prompt}]

    async with self.client.messages.stream(
        model=self.model,
        system=system_prompt,
        messages=messages,
        max_tokens=max_tokens,
        temperature=temperature,
    ) as stream:
        async for text in stream.text_stream:
            yield StreamChunk(text=text)
        # final chunk
        message = await stream.get_final_message()
        yield StreamChunk(text="", finish_reason=message.stop_reason or "stop")
```

**`backend/llm/deepseek_provider.py`** / **`minimax_provider.py`**：使用 OpenAI SDK 的 `chat.completions.create(stream=True)`，遍历 `chunk.choices[0].delta.content`：

```python
async def generate_stream(
    self, system_prompt: str, user_prompt: str, **kwargs
) -> AsyncIterator[StreamChunk]:
    messages = [
        {"role": "system", "content": system_prompt},
        {"role": "user", "content": user_prompt},
    ]
    stream = await self.client.chat.completions.create(
        model=self.model, messages=messages, stream=True,
        max_tokens=kwargs.get("max_tokens", self.default_max_tokens),
        temperature=kwargs.get("temperature", self.default_temperature),
    )
    async for chunk in stream:
        delta = chunk.choices[0].delta.content or ""
        if delta:
            yield StreamChunk(text=delta)
        if chunk.choices[0].finish_reason:
            yield StreamChunk(text="", finish_reason=chunk.choices[0].finish_reason)
            return
```

**关键点：**
- `messages.stream` / `chat.completions.create(stream=True)` 都是 SDK 原生支持，本次只是把 `await response` 换成 async iterator
- 最后一个 chunk 携带 `finish_reason`，UI 据此判定"写完了"

### 4.3 Backend — Stage4 流式写入

#### 4.3.1 `backend/api/stage4_writing.py`

新增 `_write_scene_chapter_stream()`（旧 `_write_scene_chapter()` 不变，保持所有现有测试通过）：

```python
async def _write_scene_chapter_stream(
    *,
    project_id: str,
    chapter_number: int,
    scene_number: int,
    draft_factory: Optional[Callable[[int, int], AsyncIterator[str]]] = None,
    breaker_result_override: Optional[str] = None,
    on_chunk: Callable[[str], Awaitable[None]],  # 每 50 字符 / 80ms 触发
) -> AsyncIterator[Dict[str, Any]]:
    """Yield intermediate status dicts: {event: "chunk"|"done"|"failed", ...}.

    Final yielded dict has event="done" with full draft_text + meta, OR
    event="failed" with error. Each chunk-dict has text + word_count_so_far.
    """
    # ... 内存组装 L0/L1/L2/L3/L4 + character context (与旧 _write_scene_chapter 共享)
    # 调 writer.write_scene_stream() 而非 write_scene()
    buffer = ""
    last_flush_time = time.time()

    # 注意：Python 不允许 yield 出现在非 async-generator 的 async def 里。
    # flush 逻辑必须直接写在 outer generator 里，不能封装到子函数。
    async def try_flush(force: bool = False):
        """Return a chunk event dict if flush happened, else None. Side effect:
        invokes on_chunk() and resets buffer."""
        nonlocal buffer, last_flush_time
        if not (force or len(buffer) >= 50 or (time.time() - last_flush_time) >= 0.08):
            return None
        await on_chunk(buffer)
        ev = {"event": "chunk", "text": buffer}
        buffer = ""
        last_flush_time = time.time()
        return ev

    try:
        if draft_factory is not None:
            # test seam: draft_factory is an async iterator of strings
            async for text in draft_factory(chapter_number, scene_number):
                buffer += text
                ev = await try_flush()
                if ev is not None:
                    yield ev
        else:
            async for stream_chunk in writer.write_scene_stream(
                genre=..., concept=..., ...
            ):
                buffer += stream_chunk.text
                force = stream_chunk.finish_reason is not None
                ev = await try_flush(force=force)
                if ev is not None:
                    yield ev

        # ... 拼装 final draft_text = buffer 累积的所有 chunk 文本 ...
        # ... 跑 Fact Guard / StoryOS / MemoryOS 更新（复用旧逻辑）...
        # breaker_result_override 用于测试 Fact Guard 路径："passed"/"force_pass"/"skipped"
        final_status = breaker_result_override or "completed"
        yield {"event": "done", "draft_text": ..., "status": final_status}

    except Exception as e:
        yield {"event": "failed", "error": str(e), "partial_text": buffer}
```

**关键点：**
- `_write_scene_chapter` 旧函数保留（同步路径仍有 reviewer / 手动模式调用）
- 新 `_write_scene_chapter_stream` 是 async generator，按 flush 边界 yield 增量 + 最终结果
- Fact Guard / StoryOS / MemoryOS 等"写完之后"的步骤保持同步执行（不变），不影响用户体验（这些通常 < 1s）

#### 4.3.2 `backend/conductor/stage4_async_executor.py`

新增 `AsyncStage4Executor._write_scene_stream()`（与旧 `_write_scene()` 并列；旧方法保留不变，签名 `(self, item, project_id)` 与新方法一致）：

```python
async def _write_scene_stream(self, item, project_id) -> dict:
    """Stream variant of _write_scene. Yields scene_chunk events to the
    broadcaster + persists each chunk to SceneChunkStore. Returns the same
    shape as _write_scene() for runner compatibility.
    """
    # 沿用现有 _write_scene 的 mgr 构造方式（不外传 mgr 参数）
    mgr = self._mgr_for(project_id)
    chunk_store = SceneChunkStore(
        self._projects_dir, project_id,
        item.chapter_number, item.payload["scene_number"],
    )
    chunk_store.clear()  # 起步时清空（防上轮残留）

    self._broadcaster.publish("scene_start", {
        "chapter_number": item.chapter_number,
        "scene_number": item.payload["scene_number"],
    })

    accumulated_text = ""

    async def on_chunk(text: str) -> None:
        nonlocal accumulated_text
        record = chunk_store.append(text)
        accumulated_text += text
        self._broadcaster.publish("scene_chunk", {
            "seq": record.seq,
            "chapter_number": record.chapter_number,
            "scene_number": record.scene_number,
            "text": record.text,
        })

    try:
        async for event in _write_scene_chapter_stream(
            project_id=project_id,
            chapter_number=item.chapter_number,
            scene_number=item.payload["scene_number"],
            on_chunk=on_chunk,
        ):
            if event["event"] == "done":
                self._broadcaster.publish("scene_done", {
                    "chapter_number": item.chapter_number,
                    "scene_number": item.payload["scene_number"],
                    "status": event["status"],
                    "total_chars": len(accumulated_text),
                })
                chunk_store.clear()
                _maybe_enqueue_archival(mgr, self._projects_dir, project_id,
                                        item.chapter_number)
                return {"status": "ok", "scene_status": event["status"]}
            elif event["event"] == "failed":
                self._broadcaster.publish("scene_failed", {
                    "chapter_number": item.chapter_number,
                    "scene_number": item.payload["scene_number"],
                    "error": event["error"],
                    "partial_text": event["partial_text"],
                })
                chunk_store.clear()
                return {"status": "fail", "error": event["error"]}
    except Exception as e:
        self._broadcaster.publish("scene_failed", {
            "chapter_number": item.chapter_number,
            "scene_number": item.payload["scene_number"],
            "error": str(e),
            "partial_text": accumulated_text,
        })
        chunk_store.clear()
        raise
```

注意：`_write_scene_stream()` 与现有 `_write_scene()` 共享 `_maybe_enqueue_archival()` 辅助（已在 `stage4_async_executor.py` 定义）；executor 需要新增 `self._broadcaster` 字段（构造时注入；如不可注入则改为模块级 broadcaster 单例，与 SSE 端点共用）。`AsyncTaskExecutor` Protocol 新增 `execute_stream()` 抽象方法；`AsyncAutopilotRunner._step_one()` 优先调 `executor.execute_stream()`，回退到 `executor.execute()`（用于 FakeStage4Executor 的测试场景未升级时）。

### 4.4 Backend — 独立 SSE 端点

`backend/api/autopilot.py` 新增端点。**重连补发机制基于 `Last-Event-ID` HTTP 头（浏览器 EventSource 自动管理），不再使用 `?since_seq=` 查询参数**——两个机制并存会导致客户端行为不一致，只保留一个：

```python
@router.get("/chapter-stream")
async def chapter_stream(
    project_id: str,
    request: Request,
    last_event_id: Optional[int] = Header(None, alias="Last-Event-ID"),
):
    # 项目不存在：返回 404 JSON（非 SSE，因为 EventSource 无法解析 404 的 text/event-stream）
    err = _ensure_project_exists(project_id)
    if err is not None:
        return err

    # 找到当前活跃场景（从 session.json 读 current_task）
    s = _read_raw_session(project_id)
    if s is None:
        return JSONResponse(
            status_code=404,
            content={"error": True, "code": "SESSION_NOT_FOUND",
                     "message": "无 autopilot session", "detail": {}},
        )
    current = s.get("current_task") or {}
    if current.get("kind") != "write_scene":
        # 当前不在写 scene → 返回 idle 事件，关闭流
        async def idle_gen():
            yield _format_sse("idle", {"reason": "no_active_write_scene"})
        return StreamingResponse(idle_gen(), media_type="text/event-stream")

    chapter = current.get("chapter_number")
    scene = int((current.get("scene_id") or "0-0").split("-")[1] or 0)

    chunk_store = SceneChunkStore(
        settings.projects_dir, project_id, chapter, scene
    )

    # 心跳期间持续校验 current_task 是否仍为 write_scene；若中途切到 archival/None，
    # 主动发 idle 事件并 close 流（防止订阅者继续等待永远不到的场景事件）
    last_task_check_time = 0.0

    async def event_stream():
        nonlocal last_task_check_time
        # 重连补发：从 Last-Event-ID 头取 seq（N 表示已收到 seq ≤ N），补发 N+1 起的所有 chunks
        since_seq = last_event_id or 0
        for record in chunk_store.read_since(since_seq):
            yield _format_sse("scene_chunk", {
                "seq": record.seq,
                "chapter_number": record.chapter_number,
                "scene_number": record.scene_number,
                "text": record.text,
            }, id_=record.seq)
        # 实时订阅
        async for ev in broadcaster.subscribe(last_event_id):
            # 每 5 秒复查一次 current_task，防止订阅者错过中途切换
            now = asyncio.get_event_loop().time()
            if now - last_task_check_time > 5.0:
                last_task_check_time = now
                cur = (_read_raw_session(project_id) or {}).get("current_task") or {}
                if cur.get("kind") != "write_scene":
                    yield _format_sse("idle", {"reason": "current_task_changed"})
                    return
            if ev.event in ("scene_chunk", "scene_done", "scene_failed", "scene_start"):
                yield _format_sse(ev.event, ev.data, id_=ev.id)
            elif ev.event == "heartbeat":
                yield b":hb\n\n"
            await asyncio.sleep(0)

    return StreamingResponse(event_stream(), media_type="text/event-stream")
```

**关键点：**
- 复用现有 `SSEBroadcaster`（不新建第二套），但只过滤出 4 类 scene_* 事件
- 重连补发：从 `Last-Event-ID` 头取 seq，补发之后的 chunks，按序发；浏览器 EventSource 自动管理该头
- 心跳沿用 30s 间隔（`HEARTBEAT_INTERVAL = 30.0`）
- 当 `current_task.kind !== "write_scene"` 时立即发 `idle` 事件并关流（不需要长连接占资源）
- 流进行中每 5 秒复查一次 `current_task.kind`，防止场景中途切到 archival 后订阅者错过事件

```ts
export type ChapterStreamEvent =
  | { event: "scene_start"; data: { chapter_number: number; scene_number: number } }
  | { event: "scene_chunk"; data: { seq: number; chapter_number: number; scene_number: number; text: string } }
  | { event: "scene_done"; data: { chapter_number: number; scene_number: number; status: string; total_chars: number } }
  | { event: "scene_failed"; data: { chapter_number: number; scene_number: number; error: string; partial_text: string } }
  | { event: "idle"; data: { reason: string } };

/**
 * Open an EventSource for /chapter-stream.
 *
 * 重连补发机制：浏览器 EventSource 自动把最近收到的 SSE `id` 字段填到
 * Last-Event-ID 请求头。后端据此补发遗漏的 chunks。
 * 不暴露 ?since_seq 参数——避免与 Last-Event-ID 行为冲突。
 */
export function connectChapterStreamSSE(
  projectId: string,
  callbacks: {
    onEvent: (ev: ChapterStreamEvent) => void;
    onError: () => void;
  },
): { close: () => void } {
  const url = new URL(
    `/api/v1/projects/${projectId}/autopilot/chapter-stream`,
    window.location.origin,
  );
  const es = new EventSource(url.toString());
  for (const evt of ["scene_start", "scene_chunk", "scene_done", "scene_failed", "idle"] as const) {
    es.addEventListener(evt, (e) => {
      callbacks.onEvent({
        event: evt,
        data: JSON.parse((e as MessageEvent).data),
      } as ChapterStreamEvent);
    });
  }
  es.onerror = () => callbacks.onError();
  return { close: () => es.close() };
}
```

#### 4.5.2 `frontend/src/hooks/useChapterStream.ts`（新增）

```ts
import { useEffect, useRef, useState } from "react";
import { connectChapterStreamSSE, ChapterStreamEvent } from "../api/autopilot";

export interface ChapterStreamState {
  /** All accumulated scene text, in order. */
  text: string;
  /** Highest seq seen; survives reconnects (browser-managed Last-Event-ID). */
  lastSeq: number;
  /** True while streaming (scene_start received, scene_done not yet). */
  active: boolean;
  /** True if writer failed; partial_text frozen. */
  failed: boolean;
  /** Error message if failed. */
  error: string | null;
  /** Total chars accumulated. */
  charCount: number;
  /** Current chapter/scene being written, or null. */
  current: { chapter: number; scene: number } | null;
}

export function useChapterStream(projectId: string) {
  const [state, setState] = useState<ChapterStreamState>({
    text: "", lastSeq: 0, active: false, failed: false,
    error: null, charCount: 0, current: null,
  });
  const handleRef = useRef<{ close: () => void } | null>(null);
  const cancelledRef = useRef(false);
  // Monotonic counters kept in refs so event handler closures stay accurate
  // across renders and don't trigger stale-closure bugs in async callbacks.
  const lastSeqRef = useRef(0);
  const currentSceneRef = useRef<{ chapter: number; scene: number } | null>(null);
  // Reconnect dedup: prevent multiple in-flight reconnect timers stacking up
  // when onError fires repeatedly before the previous retry resolves.
  const reconnectTimerRef = useRef<ReturnType<typeof setTimeout> | null>(null);

  useEffect(() => {
    cancelledRef.current = false;
    const open = () => {
      if (cancelledRef.current) return;
      handleRef.current = connectChapterStreamSSE(projectId, {
        onEvent: (ev) => {
          if (ev.event === "scene_start") {
            // 新场景开始：硬重置 buffer + counters（不接受上一场景的 stale chunks）
            lastSeqRef.current = 0;
            currentSceneRef.current = {
              chapter: ev.data.chapter_number,
              scene: ev.data.scene_number,
            };
            setState({
              text: "", lastSeq: 0, active: true, failed: false,
              error: null, charCount: 0,
              current: currentSceneRef.current,
            });
          } else if (ev.event === "scene_chunk") {
            // Stale-chunk guard: chunks for a previous scene (whose seq < 
            // current lastSeqRef, or whose chapter/scene != currentSceneRef)
            // must be ignored — they would corrupt the buffer.
            const cur = currentSceneRef.current;
            if (!cur) return;
            if (ev.data.chapter_number !== cur.chapter ||
                ev.data.scene_number !== cur.scene) return;
            if (ev.data.seq <= lastSeqRef.current) return;  // already seen
            lastSeqRef.current = ev.data.seq;
            setState((prev) => ({
              ...prev,
              text: prev.text + ev.data.text,
              lastSeq: lastSeqRef.current,
              charCount: prev.charCount + ev.data.text.length,
              active: true,
              current: cur,
            }));
          } else if (ev.event === "scene_done") {
            setState((prev) => ({ ...prev, active: false }));
          } else if (ev.event === "scene_failed") {
            // partial_text dedup: if our buffer is non-empty (we got chunks
            // before the failure), the chunks already contain all the text;
            // adding partial_text would duplicate. Only use partial_text when
            // the buffer is empty (writer failed before yielding any chunk).
            setState((prev) => ({
              ...prev,
              active: false,
              failed: true,
              error: ev.data.error,
              text: prev.text || (ev.data.partial_text ?? ""),
            }));
          } else if (ev.event === "idle") {
            // 当前不在写场景：buffer 保留为 last seen（用户切回 cockpit
            // 时仍能看到上一次写了什么），active=false
            setState((prev) => ({ ...prev, active: false }));
          }
        },
        onError: () => {
          handleRef.current?.close();
          if (reconnectTimerRef.current !== null) return;  // 重连去重
          reconnectTimerRef.current = setTimeout(() => {
            reconnectTimerRef.current = null;
            if (!cancelledRef.current) open();
          }, 2000);
        },
      });
    };
    open();
    return () => {
      cancelledRef.current = true;
      if (reconnectTimerRef.current !== null) {
        clearTimeout(reconnectTimerRef.current);
        reconnectTimerRef.current = null;
      }
      handleRef.current?.close();
    };
  }, [projectId]);

  return state;
}
```

## 五、错误处理

| 场景 | 行为 |
|---|---|
| LLM provider 不支持流式（理论上的未来 provider） | `generate_stream()` 抛出 `NotImplementedError`；executor 捕获并 `publish("scene_failed", {error: "stream unsupported"})`；UI 显示"✗ 写入失败" |
| 流中断（网络断） | executor publish 最后一次 flush 后的部分 chunks；SSE 端点 close；前端 onError 触发退避重连；ChunkStore 保留未清理的 jsonl；重连时补发 |
| 用户刷新页面（断 SSE） | 前端重连时 lastSeq=0（state 未持久化）；ChunkStore 补发所有 chunks；buffer 重建 |
| 用户停止托管（state=stopped） | executor 捕获 CancellationError；publish `scene_failed` with partial_text；ChunkStore.clear()；SSE 关闭 |
| 用户暂停（state=paused） | 同上，但 partial_text 保留在 ChunkStore；resume 时从 ChunkStore 读回（**待实现，本次暂不处理 resume 续写**） |
| executor 抛异常（非 LLM） | 顶层 try/except publish `scene_failed` + clear() + 抛给 runner；runner 沿用现有 fail_current_task() 路径 |
| ChunkStore append 时 IO 错误 | 记录日志但不影响流（流靠 broadcaster.publish；chunk_store 只是持久化兜底）；下次重连时从 broadcaster history 补发 |
| 当前任务不是 write_scene（archival 等） | SSE 端点立即发 `idle` 事件并关流；ChapterStreamPanel 显示"○ 空闲 · 最近 N 字"，保留上一场景文本 |
| 浏览器禁用 EventSource | fallback：polling `GET /chapter-stream?since_seq=N` 的 fetch 版（**本次不实现，作为未来工作**） |

## 六、SSE 事件契约总览

| 事件 | data 字段 | 触发时机 |
|---|---|---|
| `scene_start` | `{chapter_number, scene_number}` | executor._write_scene_stream 起步 |
| `scene_chunk` | `{seq, chapter_number, scene_number, text}` | 每 50 字符 / 80ms 一次 |
| `scene_done` | `{chapter_number, scene_number, status, total_chars}` | writer 流结束 + Fact Guard 等通过 |
| `scene_failed` | `{chapter_number, scene_number, error, partial_text}` | writer 抛错 / Fact Guard 阻塞后 force-pass 仍失败 / 托管停止 |
| `idle` | `{reason}` | 当前 task 不是 write_scene（无文本输出） |

**Last-Event-ID 语义：** 每个 `scene_chunk` 的 SSE id = record.seq。前端 `EventSource` 自动带 `Last-Event-ID` 头；后端据该头补发。**这是唯一的重连机制——前端不要用 `?since_seq=` 查询参数，行为会冲突。**
