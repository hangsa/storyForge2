**Goal:** 手动模式下, 左侧 `ChapterTreePanel` 的章节列表展示每个章节/场景的稿件写作状态, 让用户一目了然地看到"哪些章节已经写完, 哪些还在写/没写", 与 plotPilot 视觉风格保持一致。

**Architecture:** 在 `progress.json`(已经存在的唯一权威来源)和磁盘 `draft.md`(已经存在的稿件标记)之上做派生展示; 新增 1 个只读 REST 端点(`GET /stage4/scene-drafts`)专门为场景级状态服务; 前端 `WorkspacePage` 作为状态所有者, `ChapterTreePanel` 保持纯展示组件。

**Tech Stack:** FastAPI(Python)后端 · React 18 + Vite + Tailwind 前端 · vitest(组件测试)+ pytest(后端测试)

## 一、目标与非目标

### 1.1 Goal

- 手动模式下, 左侧 `ChapterTreePanel` 每个章节行展示一个状态徽标:
  - `✓` 绿色(emerald): 已完成 (`progress.status ∈ {completed, force_passed, skipped}`)
  - `✎` 蓝色(blue): 撰写中 (`progress.status === "in_progress"`)
  - `○` 灰色(gray): 未写 (缺章节 `progress.json` 条目 OR `status === pending`)
- 在当前展开章节的场景列表里, 每个场景前面挂一个小圆点:
  - `●` 实心: 该场景的 `draft.md` 文件存在且非空
  - `○` 空心: 该场景无稿件(或文件为空)
- 与 plotPilot `ChapterList.vue:39-53` 的"已收稿/未收稿"实现视觉对位。

### 1.2 Non-goals (v1.10)

- 不做"只显示未完成"过滤器
- 不做"跳到下一未写场景"快捷按钮
- 不做"正在被 autopilot 写入"的实时徽标(那是 `AutopilotMiddlePanel` 的职责, 不是本章列表的职责)
- 不改 `progress.json` 写入路径或字段
- 不改编辑器加载草稿的逻辑(`getSceneDraft` 单场景接口原样保留)
- 不做卷级别的"已写 N/M"聚合数字(留待后续迭代基于本章使用反馈再评估)

## 二、数据源与 API

### 2.1 磁盘现状(已存在, 不做改动)

- `projects/<project_id>/progress.json` — `stage4_writing.py:494` 写入. 章节结构:
  ```json
  {
    "chapters": [
      { "chapter_number": N, "status": "pending|in_progress|completed|force_passed|skipped", "scenes": [...] }
    ],
    "total_chapters": ...
  }
  ```
- `projects/<project_id>/chapters/<NN>/scenes/scene_<NNN>_draft.md` — `stage4_writing.py:177` 写入. 文件存在 + `read_text().strip() != ""` 视为"有稿件"。

### 2.2 新增 REST 端点

```
GET /stage4/scene-drafts?project_id=<id>&chapter_number=<N>
→
{
  "chapter_number": N,
  "scenes": Array<{
    "scene_number": number,    // 与 outline.json scene_plan[i].scene_number 对齐
    "has_draft": bool
  }>
}
```

**实现要点(在 `backend/api/stage4_writing.py` 内, 与既有 `get_scene_draft` 同模块):**

1. 读 `projects/<id>/outline.json`(用 `file_manager.read_json`)
2. 取该章节的 `scene_plan`; 若 outline 缺失/章节不在 outline 中 → 返回 `{chapter_number, scenes: []}` 而非 404(允许章节暂无 outline 的状态)
3. 对每个 `scene_number`, 检查 `projects/<id>/chapters/<NN>/scenes/scene_<NNN>_draft.md`
4. `has_draft = (path.is_file() and path.read_text(...).strip() != "")`
5. 端点是只读的, 无副作用, 无 LLM

**错误处理:**

- 项目 ID 不存在 → 404(`detail.message = "项目 <id> 不存在"`)
- outline 缺失或该章节不在 outline 中 → 返回 `scenes: []`(空集; 不视为错误)
- 其他文件读取异常 → 500(开发可观测, 不静默)

### 2.3 既有 API 复用

- `GET /stage4/progress?project_id=<id>` — 已经被 `WorkspacePage.tsx:230-253` 拉取并存到 `chapters` state. 本次只是把同一个数组转成 `chapterStatus` 映射传给 `ChapterTreePanel`.

### 3.2 渲染规则

**章节行(后缀位置):**

- 章节行右边原本有"`{N} 场景`"计数 (在当前选中章节上); 在新设计里, 把计数移到左侧(已经在那个位置? 待确认), 状态徽标放到右上角.
- 当 `chapterStatus[c.chapter_number]` 存在时, 渲染 `<span data-testid="chapter-status-{N}">{icon}</span>`:
  - `"completed"` → `✓`, className 含 `bg-emerald-100 text-emerald-700`
  - `"writing"` → `✎`, className 含 `bg-blue-100 text-blue-700`
  - `"planned"` → `○`, className 含 `bg-gray-100 text-gray-500`
- 缺省时(`chapterStatus` 整体未提供)什么都不渲染 —— 保持向后兼容(空状态时不显得突兀)

**场景行(前缀位置):**

- `sceneStatus[s.scene_id] === true` → `●` 实心蓝/绿
- `sceneStatus[s.scene_id] === false` → `○` 空心灰
- `sceneStatus` 整体未提供 或 该 key 不存在 → 不渲染状态点
- 测试 ID: `scene-status-{scene_id}`(包装一个`<span data-testid>`, 通过 textContent 检验)

### 3.3 `WorkspacePage.tsx` 状态接入

```ts
// 既有 chapters state 已经持有 [{ chapter_number, status }] 结构(stage4 progress)
const chapterStatus = useMemo<Record<number, ChapterStatus>>(() => {
  const m: Record<number, ChapterStatus> = {};
  for (const c of chapters) {
    if (c.status === "completed" || c.status === "force_passed" || c.status === "skipped") m[c.chapter_number] = "completed";
    else if (c.status === "writing") m[c.chapter_number] = "writing";
    else m[c.chapter_number] = "planned";
  }
  return m;
}, [chapters]);

// 新增 sceneStatus state
const [sceneStatus, setSceneStatus] = useState<Record<string, boolean>>({});

// 新增 useEffect: 当 currentChapter 变化时, 拉一次场景稿件可用性
useEffect(() => {
  if (!projectId) return;
  let cancelled = false;
  api.getSceneDrafts(projectId, currentChapter)
    .then((r: { scenes: Array<{ scene_number: number; has_draft: boolean }> }) => {
      if (cancelled) return;
      setSceneStatus((prev) => {
        // 仅替换当前章节的 entries, 保留其他章节的缓存
        const next = { ...prev };
        for (const k of Object.keys(next)) {
          if (k.startsWith(`${currentChapter}-`)) delete next[k];
        }
        for (const s of r.scenes ?? []) {
          next[`${currentChapter}-${s.scene_number}`] = s.has_draft;
        }
        return next;
      });
    })
    .catch(() => {
      // 失败: 显式清空当前章节的 entries, UI 退回到"未知"状态.
      if (cancelled) return;
      setSceneStatus((prev) => {
        const next = { ...prev };
        for (const k of Object.keys(next)) {
          if (k.startsWith(`${currentChapter}-`)) delete next[k];
        }
        return next;
      });
    });
  return () => { cancelled = true; };
}, [projectId, currentChapter, reloadKey]);  // reloadKey 让"刷新"按钮也触发重拉
```

### 3.4 `api/client.ts` 新增

```ts
interface SceneDraftStatus { scene_number: number; has_draft: boolean; }

async function getSceneDrafts(
  projectId: string,
  chapterNumber: number,
): Promise<{ chapter_number: number; scenes: SceneDraftStatus[] }> {
  const data = await request<{ chapter_number: number; scenes: SceneDraftStatus[] }>(
    "GET",
    `/stage4/scene-drafts?project_id=${encodeURIComponent(projectId)}&chapter_number=${chapterNumber}`,
  );
  return data;
}
```

镜像 `getSceneDraft`(line 879) 的实现方式, 用同一 `request` helper.

## 四、错误处理

| 场景 | 行为 |
|---|---|
| 后端 outline.json 缺失 | `/stage4/scene-drafts` 返回 `{scenes: []}`; 前端 `sceneStatus` 对该章节为空(无徽标)|
| 后端 `scene_plan` 为空 | 同上 |
| 后端 `draft.md` 文件缺失 | `has_draft = false` |
| 后端 `draft.md` 内容为空白字符串 | `has_draft = false` |
| 后端 `draft.md` 不可读(权限等) | 抛 500; 前端 catch 后清空当前章节的 `sceneStatus`, 不弹 toast(与现有"未知"语义一致)|
| 前端 `getSceneDrafts` 失败(网络/5xx) | 同上, 静默清空 |
| 前端 `getStage4Progress` 失败 | 已经是空状态(章节列表为空); `chapterStatus` 也是空, 无徽标 |
| 章节存在于 outline 但不在 progress.json | `chapterStatus[N] = "planned"`(由 useMemo 的 fallback 分支处理)|
| 用户点"刷新"按钮 | `reloadKey++` 让现有 `useEffect` 重跑; 同时让本特性的 `useEffect` 也重跑(依赖列表包含 `reloadKey`)|

所有错误路径遵循项目现有的"我们不知道磁盘上有什么"的诚实-空-状态模式.
